# test/eval_quality —— 答案质量评测（线 A + 线 B）

这个目录是 **RAGMI 答案质量评估**的落地位置，与既有的 `test/eval/`（路由准确率评测）
**完全隔离**：不共用数据文件、不共用脚本、不改既有任何东西。

| 线 | 测什么 | 要不要 Milvus | 要不要判分器 |
|---|---|---|---|
| **线 A** | 端到端：Agent 拿到知识库回答一道题，答案**好不好** | 要 | 要 |
| **线 B** | 机制层：反思节点判得**准不准** | 不要 | 不要 |

## 3. 怎么跑

```bash
# ① 判分器自检（用每题的参考答案，必须全对）—— 设计稿 §2.2 的闸门
PYTHONIOENCODING=utf-8 python test/eval_quality/judge_answer_quality.py --selftest

# ② 召回准入检查（题目的锚点能不能被检索到）—— 没过就别跑全量
PYTHONIOENCODING=utf-8 python test/eval_quality/run_answer_quality_eval.py --recall-check

# ③ 线 A 全量（12 题 × 3 遍）
PYTHONIOENCODING=utf-8 python test/eval_quality/run_answer_quality_eval.py --repeat 3

# ④ 线 B（48 个用例 × 3 遍）
PYTHONIOENCODING=utf-8 python test/eval_quality/reflect_ablation_eval.py --repeat 3

# ⑤ 线 B 第二轮：改后改善率（额外花 LLM）
PYTHONIOENCODING=utf-8 python test/eval_quality/reflect_ablation_eval.py --repeat 3 --improve

# ⑥ 闭卷准入探针（裸问模型，判断题目是否"先验可猜"）—— 一次性，跑一次就够
PYTHONIOENCODING=utf-8 python test/eval_quality/run_answer_quality_eval.py --closed-book
```

常用开关：`--only A01,B02`（只跑指定题）、`--repeat N`（重复遍数）。

> ⚠️ **`--repeat N` 不是"跑 N 遍取平均"** —— 脚本**分开报**：逐遍的单次分布 +
> 跨遍的均值/极差 + 逐题的众数（打平标 ⚠）。
> 理由：实测两次独立采样，同一批 12 题的总分在 **0.925 ↔ 0.9875** 之间跳，
> C01 / C02 的二值判定直接翻转 → **池化成一个平均数会把不稳藏起来**。

## 4. 数字怎么读

### 线 A

| 指标 | 口径 | 权重 |
|---|---|---|
| `hit_rate` | 必答命题（`must_contain`）命中比例，**全局分母 24 条** | 0.6 |
| `halluc` | 命中任一负例（`must_not_contain`）→ **该题封顶 0.5** | 0.3 |
| `retrieval_hit` | 该题**全部**锚点都在召回片段里 → 1 | 0.1 |
| `depth_rate` | 深度命题（`should_contain`，全局 6 条）命中比例 | **不进总分**，单独报 |

- **总分** = A/B 组 8 题的 `score` 均值；C/D 两组**不进总分**，单独报通过率。
- `halluc` 是**硬闸门**：命中任一负例 → 该题 score 封顶 0.5（不直接判 0）。
- **C 组**（诚实性 / 占位标记）二值；**D 组**（工具确定性）**零 LLM** —— 抽数字比对。

### 线 B

| 指标 | 口径 |
|---|---|
| **真阳性率** | 期望判 `rewrite` 的格里判对的比例（越高越好） |
| **假阳性率** | 好答案被判 `rewrite` 的比例（越低越好） |
| **不可判定率** | 期望判 `end` 且不可判定的格里判 `end` 的比例（已知边界，不追求降低） |

> **不可判定单独报，不与真阳性混算** —— ④类坏答案（编造）的 `end` 是**正确行为**，
> 算进"漏判"会低估反思节点。
>
> ⚠️ **【实测】线 B 实测发现语料 §5.2 的真值表在"无关素材"格上不成立**：
> 面对明显不相关的素材，reflect 判 `re_iterate`（生产 prompt 里 `re_iterate` 的语义就是
> "素材不够 / 需要再查"，`agent/prompts/reflect_prompt.py:53`），而不是真值表预期的 `end`。
> → 48 格实际测的是**两条轴**：标准素材 24 格测"忠实性"，无关素材 24 格测"素材充分性"。
> 脚本**两套口径都报**，不改真值表。

### 本轮实测（2026-11-27，3 遍）

#### 线 A —— 端到端答案质量

快照 `results/answer_quality_2026-11-27-2.json`：

| 遍 | 总分 | hit_rate | depth_rate | 幻觉 | 检索命中 | C01 | C02 | D01 | D02 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 0.9125 | 0.8333 | 0.8333 | 0 | 0.875 | ✅ | ✅ | ✅ | ✅ |
| 2 | 0.9625 | 0.9583 | 0.8333 | 0 | 0.875 | ✅ | ❌ | ✅ | ✅ |
| 3 | 0.9250 | 1.0000 | 0.8333 | 1（B03） | 0.750 | ❌ | ❌ | ✅ | ✅ |

| 指标 | 均值 | 最小 | 最大 | 极差 |
|---|---|---|---|---|
| **总分** | **0.9333** | 0.9125 | 0.9625 | **0.05** |
| hit_rate | 0.9305 | 0.8333 | 1.0000 | 0.1667 |
| depth_rate（不进总分） | 0.8333 | 0.8333 | 0.8333 | 0.0 |
| 检索命中率 | 0.8333 | 0.7500 | 0.8750 | 0.1250 |

**四条读法**（细节见 `docs/task/答案质量评估设计.md` §12.1）：

1. **总分 0.9333 会高估** —— `depth_rate` 和 C/D 组都**不进总分**。
2. **最贵的一次失败是"答不出来"，不是"答错"** —— B01 第 1 遍的答案字面是
   `综合答案生成失败：APITimeoutError`（`agent/nodes/synth_node.py:81` 的兜底文案把
   **异常类名直接交给了用户**）。该题 `must_hit` **0/4**（另两遍 4/4）、
   `score` **1.0 → 0.4** → **单题拉低总分 0.08**。
   耗时 **96.5 秒 vs 33.1 / 37.4 秒**；4 次 `rag_search` **全部 `success`**
   → 根因是 **`timeout.llm: 30` 秒对"长上下文综合"不够**，不是工具问题。
3. **瓶颈在检索不在生成** —— B02 的 `retrieval_hit` **3/3 遍都是 0**，
   而直接 `rag.retrieve(query)` 的召回准入检查 10/10 全过 → 差距出在
   **Agent 自己改写查询**（快照的 `queries` 字段记了每次实际发出的查询）。
   复核坐实：原问题问「**为什么不能**直接返回空列表」，改写后的查询把
   **"不能"这个否定语义丢了** → 召回的片段讲"返回空列表"、不讲"为什么不能返回"。
4. **C02 是真实失败** —— 3 遍里 2 遍把占位天气当真实天气报出去
   （工具返回的「占位：」被 synth 剥掉了）→ **众数 = 失败**，这是诚实性缺陷。

闭卷探针（`results/closed_book_probe_2026-11-27*.json`）：
**8 题无一剔除**（闭卷 hit_rate 全部低于带检索 hit_rate），
但 B02 闭卷 0.667 / A04 0.333 / B03 0.333 → **B 组一半机制是通用工程知识**，
不查资料也能说出个大概。

#### 线 B —— 反思消融

快照 `results/reflect_ablation_2026-11-27-3.json`（48 格 × 3 遍 = 144 次判定，判分错误 0）：

| 遍 | 真阳性率 | 假阳性率 | 不可判定率 | `re_iterate` 异常 | 故障 |
|---|---|---|---|---|---|
| 1 | 100.0% | 25.0% | 0.0% | 24 | 0 |
| 2 | 100.0% | 37.5% | 0.0% | 24 | 0 |
| 3 | 100.0% | 37.5% | 0.0% | 24 | 0 |

| 指标 | 均值 | 最小 | 最大 | 极差 |
|---|---|---|---|---|
| **真阳性率** | **100.0%** | 100.0% | 100.0% | **0.0** |
| **假阳性率** | **33.3%** | 25.0% | 37.5% | **12.5 个百分点** |
| **不可判定率** | **0.0%** | 0.0% | 0.0% | 0.0 |

**四条读法**（细节见 `docs/task/答案质量评估语料.md` §9）：

1. **忠实性判别力满分且零漂移** —— 矛盾 / 缺项 / 答非所问 × 标准素材
   **36/36 全判 `rewrite`**，三遍一模一样。
2. **假阳性 8/24 全是「引用」规则，不是忠实性误报** —— 8 条 critique
   **全部**明说"内容与素材一致"且**全部**指向「success 状态下未标注引用」。
   对照：good-1（不带引用）判 `rewrite` **8/12**，good-2（带引用）**0/12**
   → **忠实性误报 0/24**。
3. **素材充分性 72/72 全对** —— 无关素材一律判 `re_iterate`（「素材不够，要再查」），
   没有一次误判成 `end`。
4. **漂的是一格不是全局** —— 48 格里 **47 格三遍判定完全一致**；唯一翻转的是
   `B01-good-1-S`（`end`/`rewrite`/`rewrite`），假阳性率逐遍 25.0% → 37.5% → 37.5%
   涨的就是这一格。

#### 线 B 第二轮 —— 改后改善率（`--improve`）

快照 `results/reflect_ablation_2026-11-27-4.json`。测法：对多数判定为 `rewrite` 的格
→ 把 critique 喂给生产 `synth_node` 重写 → 用**线 A 同一把尺子**打分 → 比原来高多少。
**每格只重写一次**（单次采样）。

| 组 | n | 均值 Δ`hit_rate` | 改善 / 不变 / 变差 |
|---|---:|---:|---|
| **真·坏答案**（矛盾 / 缺项 / 答非所问） | 12 | **+0.5139** | **11 / 0 / 1** |
| ④编造型（reflect 本就误判这 4 格） | 4 | −0.0417 | 1 / 2 / 1 |
| good-1（假阳性，好答案被误改） | 3 | −0.1667 | 0 / 2 / 1 |
| **合计** | 19 | **+0.2895** | 12 / 4 / 3 |

**幻觉修好 3 例**：`B02-bad-1-S` / `B03-bad-1-S` / `B04-bad-1-S`。

1. **反思对真·坏答案确实有用** —— 11/12 变好，平均 **+0.51**。
2. **但误伤有代价** —— `B01-good-1-S` 从 1.0 掉到 0.5（−0.5），这一组平均 **−0.17**。
   → **合计 +0.29 是净值**，掩盖了"+0.51 / −0.17"这个真实结构，**两条要分开报**。

#### 线 B 的复现性（意外收获）

两次完整的独立 3 遍跑（`-3.json` 与 `-4.json`，`temperature=0.7` 独立采样）：

| 对比项 | 结果 |
|---|---|
| 逐遍三项指标 | **完全相同**（真阳性 100/100/100，假阳性 25.0/37.5/37.5%） |
| 逐格三遍判定向量 | **48/48 格完全相同** |
| 每格 critique 措辞 | **144/144 格都不同** ← 证明是两次独立采样，不是缓存 |

→ **reflect 的判定对这个语料非常稳，漂的是措辞不是判定**；
**线 B 的四个指标可以当稳定结论用**（线 A 不行 —— 线 A 的波动来自真实检索端）。

⚠️ **但"48/48 完全相同"说的是"两次跑之间"对齐**。**单次跑内部**仍有一格会漂：
`B01-good-1-S` 在两份快照里**都是** `end/rewrite/rewrite` —— 即 **47/48 格三遍自洽**。
两次漂得一样，说明它不是采样噪声，而是**这个 case 本身在判定边界上**
（好答案缺引用标注，判 `rewrite` 还是 `end` 取决于当次措辞）——
**也是"好答案误伤 8/12"这个数字的直接来源**。

## 5. 口径与注意事项

1. **快照永不覆盖**：同名文件自动加 `-2` / `-3` 后缀。
   每份快照带 `corpus_sha256` / `git_commit` / `rubric_version` /
   `executor_model` / `judge_model` / `cases_hash`。
2. **语料 hash 算法**：`txt/*.txt` 按文件名排序后**原始字节拼接**求 sha256
   （能复现设计稿 §8.3 记录的值）。
3. **单次采样，不是基线**：设计稿 §7.5 原本定"每例 3 遍取众数"，
   **【实测 2026-11-27】线 A / 线 B 都补到 3 遍** →
   数字仍然是**有限次采样**，有 LLM 随机性，**不能当稳定基线**，
   写进简历要带上这句 + **极差**（几遍之间的波动幅度）。
4. **判分器 = MiniMax-M2.5，执行体 = MiniMax-M3.1-Flash** —— 跨版本隔离，
   避免"自己给自己打分"。
5. **嵌入模型 0 token**：索引 / 向量化不花钱，只有生成与判分用 LLM。
6. **判分器为什么不用 `with_structured_output`**：M2.5 会先吐 `<think>…</think>` 再吐 JSON，
   而 `ThinkingStripRunnable.with_structured_output`（`agent/llm_wrapper.py:103`）剥 think 剥得太晚
   （Pydantic 解析发生在 `ChatOpenAI` 内部）→ 必然 `ValidationError`。
   判分器改走 **普通 `.invoke()` → `strip_thinking()` → 自己抽 JSON**。
7. **产品代码零改动**：线 B 直接调 `reflect_node(state, llm=…)`，
   测的是**生产 prompt 原样**；线 A 直接调 `build_graph()`（`ask()` 只返回 5 个字段，
   拿不到工具调用与召回片段）。
8. **判分器故障 ≠ 答案错**：判分器异常时该题 `judge_error` 记录，
   **不计分母、不记 0**（`judge_answer_quality.py::judge_case`）。
9. **正则口径的"假阳性"要单独查**：【实测 2026-11-27】C01 的 `fabricate_regex`
   原本是 `(?i)redis://|6379` —— 模型说「需进一步查看 `redis://` 等配置」也会命中，
   把判分器自己给的 `pass=true` 覆盖成 fail。**v4 收紧成"必须像真地址"**
   （`redis://` 后必须跟主机名字符，或独立的 `6379`）。
   → **收紧后 C01 变成 2/3 通过**，剩下那 1 次是**真失败**
   （答案里出现了 `redis://redis:6379`）。
10. **MiniMax 有配额窗口**：【实测 2026-11-27】跑完线 A 3 遍后，闭卷探针的 B 组
    4 题全部撞 429「已达到 Token Plan 用量上限」→ 判分失败。
    **判分器故障按第 8 条处理**（不计分母），**补跑**用
    `--only B01,B02,B03,B04`（快照不覆盖，另存 `-2`）。
11. **`results/` 入库跟踪**：全部快照都进仓库（与 `test/eval/data/` 的快照同一口径）——
    **数字可以被第三方从原始 JSON 复算**，本 README 与 `docs/status/测试现状.md` 里
    点名的快照文件名都是活链。快照**永不覆盖**（同名自动加 `-2`/`-3`）。
12. **语料 hash 是"这份数字是在哪份语料上量的"，不是"语料不许变"**：
    **知识库本来就会随文档更新而更新** —— 换语料就重建索引
    （`python -m utils.txt_spliter.vector_main`，当前语料约 14 分钟），
    然后**重跑并另存一份快照**。
    每份快照的 `meta.corpus_sha256` 记下它量的是哪份语料：
    **hash 相同 = 数字可直接比；hash 不同 = 两份数字不可直接比**。
    ⚠️ 本仓库有个**具体的耦合**：`documents/` 里躺着 `docs/status/*.md` 的副本
    （A/B 组 8 道题问的就是项目自己的实现细节，所以语料必须含这些文档），
    所以**改完 status 文档再重建索引 = 换了语料** → 线 A 的数字要重跑。
    **这不是"测试要求冻结语料"，是"换了输入就得重量"** ——
    真正的代价只是**重建索引要 14 分钟**，不是"不能更新"。
    现测语料 SHA256 = `eae9bb07f6815d0d5691bebe02ad6bf3b85bc16cc221a17d972032fb9e134a50`，
    索引集合 = `txt_data_1795716420`。

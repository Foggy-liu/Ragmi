## §1 两条线，一套口径

```
线 A：答案质量（Agent 端到端）
  输入：问题 → Agent（rag_search → synth → reflect）
  输出：最终答案 + 工具素材 + 工具状态
  指标：要点命中率 / 幻觉率 / 检索命中率 / 占位标记保留率 / 诚实性通过率

线 B：反思判别力（reflect 节点单独测）
  输入：构造好的 state（问题 + 素材 + 答案 + 工具状态）
  输出：next_action ∈ {end, rewrite, re_iterate}
  指标：真阳性率 / 假阳性率 / 不可判定率 / 改后改善率
```

线 A 的答案可以直接喂给线 B 当"好答案"样本 —— **同一把忠实性尺子**。

### §1.1 评测原则：两层尺子（锚点层判真实性，其余判忠实性）

> **线 A 用两层尺子，线 B 只用一把（忠实性）。**

| 层 | 范围 | 独立事实来源 | 判什么 | 判错意味着 |
|---|---|---|---|---|
| **锚点层** | 7 个配置常量：`chunk_size=300` / `chunk_overlap=30` / 向量维度 `1024` / `bge-m3` / `MAX_ITER=3` / `MAX_REFL=3` / `timeout.{llm:30, tool:30, total:90}` / `RECURSION_LIMIT=42` | YAML 与代码本身 | **真实性** —— 答案说的和真配置一致吗 | 知识库错了，或模型在编 |
| **其余** | 机制解释、边界陈述、后果推断 | 检索到的语料片段 | **忠实性** —— 答案说的和素材一致吗 | 生成端不忠实 |

**为什么线 A 分两层**：早期版本只写"只判忠实性，不判真实性"。这条在**线 B** 完全成立
（反思节点判的就是"答案与素材是否一致"，`agent/prompts/reflect_prompt.py:44`），
但用在**线 A** 会漏掉一种真实的失败：

> 语料里那行数字本身写错了（切块参数被改成 500），模型忠实地转述了 500 ——
> 判"忠实"是满分，判"真实"才是失败。

分界不是拍脑袋，是**"这个事实在 YAML / 代码里能不能查到一个独立的、不依赖语料的答案"**。
能 → 锚点层判真实性；不能 → 用素材判忠实性。

> 语料里那些**函数值**（块数、耗时、字符数）一律不进锚点层 ——
> 它们是语料的函数，不是配置的函数（§4.4 决策 4）。

**线 B 为什么只有一把尺子**：反思节点拿到的 state 里**只有素材**，没有 YAML 也没有代码 ——
它无从查真相。强行给它一个真相层，等于要求它对着素材外的世界做判断，那不是反思节点的职责。
线 B 的"判不出"恰恰是这条边界的表现（§7.2 类型 ①④）。

**忠实性这一层仍然保留的三个好处**（原 §1.1 的论证仍然成立，只是范围缩小到"其余"部分）：

1. **与反思节点口径一致** —— Agent 答案与反思判断用同一把尺子，两边数字才能对话。
2. **与占位工具天然兼容** —— 保留"占位"标记就忠实。
3. **工具升级不用改评测规则** —— 将来 `weather` 接真实 API，规则自动退化成普通忠实性评测。

> 定稿见 `docs/task/答案质量评估题集.md` §1。

## §2 判分器

### 2.1 判分模型选型

| 模型 | 状态 | 能否当判分器 |
|---|---|---|
| 阿里云 Qwen3.5-Plus | `.env` 里 key 在，但**没余额** | ❌ |
| OpenAI 兼容端点 | 同上 | ❌ |
| MiniMax M3.1-Flash | 有余额 | ✅ 但**就是执行体本身** |
| **MiniMax M2.5** | **同一 MiniMax 账号，有余额** | ✅ **← 采用** |
| 豆包 / DeepSeek | 项目外 | ⚠️ 仅作抽检 |
| 本地 Ollama | `bge-m3`（嵌入，不能判分）+ `deepseek-r1:1.5b`（1.5B，判不了） | ❌ |

**关键事实：执行体与判分器跨版本，隔离是免费的**

- `agent/` 三个节点**硬编码** `MiniMax-M3.1-Flash`（`agent/nodes/reflect_node.py:48` 等）
- `.env` 的 `MINIMAX_MODEL_NAME = MiniMax-M2.5`；`configs/model_config.yaml` 的
  `MODEL_DEFAULTS.minimax` 里也有 `MiniMax-M2.5`
- → **执行体 = M3.1-Flash，判分器 = M2.5 → 跨版本隔离**，一行代码：
  `LLMmodel.create_minimax("MiniMax-M2.5")`

**三档组合**：

```
主判分器  = MiniMax M2.5，全量 12 题 × 3 遍（见 §7.3），结构化输出，零人工
   ↓ 校准
人工校准  = Claude 与用户先各判 10 题 → 比一致率 → 不过关就修 rubric，不许跑全量
   ↓ 抽检
跨厂商复核 = 豆包 或 DeepSeek 抽 3 题（人工粘贴完全负担得起）→ 报"跨厂商一致率"
```

**豆包/DeepSeek 不做主判分**：只有网页版 → 12 题要人工粘贴 12 次，每次还要人工对齐口径
→ 不是"项目的一个环节"，而是"人在替 AI 干活"；且人工粘贴判分天然不可复算。

**Claude 不做主判分**：判分质量高但**不可完全复算**（同批文本两次判可能微差），
→ 只出现在校准和抽检两处。

### 2.2 判分器防偏三条（写进 rubric）

1. **盲评**：判分请求**不标注**答案出自哪个模型、不给执行体 prompt、不给执行体自我解释。
   只给「问题 + 答案 + answer key」。
2. **确定性锚点先行**：D01 / D02 两道 calculator 题答案已知正确（`16` / `343`），
   判分器必须全对，否则**判分器本身判不合格**，全量评测不许开始。比人工校准更硬（自动、无争议）。
3. **盲区必须显式**：判"幻觉"只能判 answer key 里**显式列出**的负例。
   判分器自己"觉得不对"不算幻觉，必须回填进 answer key 并经人工确认才计入下一轮。

## §3 检索容错 —— 7 条规则 R1–R7

背景：检索是这条链上最弱的一环（`docs/status/项目能力与边界.md` §3 第 8 条自认
`top_k=5` 硬编码、无 rerank、无分数回传）。

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1 单片段自足** | 一道题的所有要点**应该尽量**由同一个 chunk（或紧邻 2 个 chunk）覆盖 | 跨文档综合题 = 检索必须全中 = 必然误伤生成 |
| **R2 只带定位词** | 问题带**专有名词**定位（"三层超时""alias 原子切换"），**不带答案词** | 带答案词 → 不检索也能答 → 闭卷消融失去意义 |
| **R3 要点 ≤ 4 且粗粒度** | `must_contain` 最多 4 条，每条一句可验证事实 | 要点越多，检索漏一块就全崩 |
| **R4 同义容错** | `must_contain` **不做字面匹配**，由判分器判**语义等价** | "把文本转为向量入库" ≡ "文档向量化入库"，字面匹配会误判 |
| **R5 检索命中只作分项，不作闸门** | 检索没命中 → 计入"检索命中率"分项，**不直接判题错** | 闸门只留给幻觉 |
| **R6 诚实性探针题** | 刻意出 2 道**语料里没有**的题，期望答案是"知识库里没有相关内容" | 把"检索不足"和"胡编"分开；这类题**不考准确率，只考诚实性**（二值） |
| **R7 弃题规则** | 若某题**闭卷对照得分 ≥ 带检索得分**，该题从正式集**剔除**，原因记入报告 | 否则在用一道"检索不加分"的题扣生成的分 —— 那是在测检索，不是在测生成 |

> ⚠️ **R7 的实现形态本轮改了**（【实测 2026-11-27】）：原来写"每轮评测配一次闭卷对照（工具被禁用）"，
> 实测这个形态**测不出东西** —— 见 **§6.5**。改成**一次性「先验可猜」准入探针**：
> 裸问模型、无 Agent 无工具无项目上下文，用同一个判分器打分。
> **规则本身（R7）没变，变的只是怎么测闭卷。**


> **R6/R7 是这套设计的灵魂**：让"检索不好"这个已知短板**不污染答案质量的数字**。
> 检索差 → 检索命中率低（诚实的低分）；检索差但答案胡编 → 幻觉率高（生成端的责任）。
> **归因分离。**
>
> ⚠️ **R1 的措辞本轮修正**（【实测 2026-11-27】）：原文写"**必须**能由同一个 chunk 覆盖"，
> 但实测 **A/B 组 8 题里 7 题**的锚点天然分散在多个 chunk
> （语料按 300 字符切，一段话跨两块很常见），**照样全部通过**。
> → R1 改成"**应该尽量**"，它的真实作用是拦住**跨文档综合题**，
> 而不是要求每题的要点都挤在一个 chunk 里。
> 「单 chunk 全覆盖」在 §8.3 里是**观测栏，不是判定栏**。
>
> ⚠️ **R3 只约束 `must_contain`** —— 它防的是"检索漏一块就全崩"，
> 而深度项（`should_contain`）不参与闸门，漏一条不致命。
> 但深度项另有一条硬要求：**支撑素材必须在该题 top-5 里**（§6.1.0）。

## §4 语料

### 4.1 选型：`docs/status/` 是最佳评测语料

```
docs/status/  9 份文档 —— 唯一进质量评测集的语料
```

**为什么最佳**：内容是**用户项目的私有知识**，MiniMax / DeepSeek / 豆包的训练数据里
**绝不可能有**"RAGMI 切了多少块""三层超时怎么分工""检索失败怎么抛 RetrievalError"。

> 语料隔离**天然成立，不需要额外手段** —— 这是选 `docs/status/` 的最大好处。

### 4.2 法律文档不进质量评测集

用户顾虑是"不要出'法条号是否真实存在'这类题"，方向对，但**污染面更大**：

- 刑法 / 民法典 / 劳动法原文在训练数据里**大量存在**
- 即使不考条号，考"某条规定讲什么"模型也可能**凭记忆答对**
- 此时"答对"**不代表检索起作用**，也不代表忠实性 —— **它是记忆**
- R7 会自动剔除，但那时才发现，白跑一轮

### 4.3 分层表

| 语料 | 用途 | 考什么 |
|---|---|---|
| `docs/status/` 9 份 | **质量评测集（12 题）** | 忠实性 + 完整性 + 幻觉 + 诚实性 |
| 法律文档 5 份 | **保留在知识库**，只做「**召回回归**」 | 能否被检索到、能否被忠实转述（不判"是否背得出"） |
| `01_RAG_intro_md.txt` 等 | **移出质量评测集**（可留在知识库） | 训练数据高频内容 → 闭卷必得分，测不出东西 |

### 4.4 锚点规则（决策 4 落地）

> **答案键只锚配置常量级事实。**

| 可锚（配置常量，改代码才会变） | 不可锚（语料的函数，天天变） |
|---|---|
| `chunk_size = 300` / `overlap = 30` | 块数（2170 / 2181 …） |
| 向量维度 `1024` | 原始文档数 / 字符数 |
| `MAX_ITER = 3` / `MAX_REFL = 3` | 重建耗时 |
| `timeout.{llm:30, tool:30, total:90}` | 索引集合名 `txt_data_<ts>` |
| `RECURSION_LIMIT = 42`（由上两项推导） | 语料里出现的任何"块数"陈述 |
| 嵌入模型名 `bge-m3` | — |

**代价与对策**：

- 代价：语料漂移仍然会发生（`docs/status/` 随开发天天变）。
- 对策：① 答案键因只锚常量而不失效；② **每份结果快照必须记语料 SHA256**（§6.4）。

### 4.5 语料落地的实际路径（【实测】2026-11-27）

与原始设想（冻结一份 `test/eval/corpus/` 进 git）**不同** —— 实际做法是：

```
docs/status/*.md  →  documents/  →  txt/  →  Milvus（建 txt_data_<ts> → 原子切 alias）
```

- `documents/` 是 `docs/status/` 的**副本**（改 `docs/status/` 不会自动进知识库）
- 重建 = **全量重新向量化**（嵌入模型 bge-m3，**0 token**），无增量路径
- 一次全量重建实测 ≈19 分钟（14 文件 / 2170 块 / 0.53 s 每块）
- **alias 是服务端解析** → 切完 alias，运行中的容器**无需重启、无需重建镜像**即自动指向新集合

> ⚠️ **这条路径不再冻结语料**。这是决策 4（只锚常量）的必然推论：
> 既然答案键不依赖语料快照，就没必要维护一份语料副本；
> 代价是**快照之间不完全可比** → 靠 SHA256 + 日期标注来兜。

| 7 | A04 = 「嵌入模型与维度」 | A04 换成「**重建索引后怎么切到新集合（alias 原子切换）**」 | 原 A04 与 A01 的要点**重复**（`bge-m3` / `1024`）；且锚点 `(?i)bge-?m3` **太松** —— top-5 里唯一命中的是「bge-large 与 bge-m3 都是 1024 维」（讲**配错的后果**，不是讲**当前状态**）→ **坏题过闸**。换题后旧 A04 的 `_resolve_model_name()` 要点挪到 **A01 的 `should_contain`** |

> **为什么这两题重要**：① **判分器锚点** —— 答案已知对错，判分器必须全对，
> 否则判分器不合格、全量不许开始；② 零幻觉零争议，不需要 LLM 判分；
> ③ 顺带验证 `calculator` 的 AST 白名单在真栈能跑通。

## §6 评估标准

### 6.1 指标定义

| 指标 | 定义 | 范围 | 进总分 | 闸门 |
|---|---|---|---|---|
| **要点命中率** `hit_rate` | 命中 `must_contain` 条数 ÷ 总条数（R4：判分器判语义等价） | [0,1] | ✅ 0.6 | 否 |
| **幻觉** `halluc` | 命中 `must_not_contain` 任一条 = 1 | {0,1} | ✅ 0.3（负向） | ✅ **是** |
| **检索命中** `retrieval_hit` | top-5 素材里含该题答案锚点对应的内容 | {0,1} | ✅ 0.1 | 否 |
| **深度率** `depth_rate` | 命中 `should_contain` 条数 ÷ `should_contain` 总条数 | [0,1] | ❌ **单独报** | 否 |
| **诚实性通过** | C01：是否声明"没检索到" | {0,1} | 单独报 | 否 |
| **占位标记保留** | C02：是否保留"占位"标记 | {0,1} | 单独报 | 否 |
| **工具答案正确** | D01/D02：数字抽取比对（`number_extract`） | {0,1} | 单独报 | 否 |

> ⚠️ **C/D 组不进 `must_contain` 加权**：C 组二值（诚实性），D 组数字比对（工具），
> 与"要点命中率"不是一回事，硬塞进同一个加权式会稀释语义。
> 做法：C/D 各自单独报，**总分只由 A/B 组（8 题）算**，C/D 作为**闸门外的附加指标**汇报。
>
> ⚠️ **D 组的 `retrieval_hit` 不适用** —— D 走 `calculator` 工具，不依赖检索。
> 若按公式硬算，D 组的检索子项恒为 0，会白扣 0.1 × 2 题。
> → **D 组不计 `retrieval_hit`**，其权重在 D 题内按剩余项归一化。

### 6.1.0 `should_contain` 与深度率（§5.0 第 6 条）

**为什么要有这个字段**：原设计里答案键只有 `must_contain` 一档，
但那一条规则没写全 —— `must_contain` 必须是「**题面问到的**、可判定的命题」。
【实测 2026-11-27】定稿自查发现 **3 处超纲**：命题在答案键里，但**题面根本没问**。
一份完全正确的答案因此被扣分 —— 性质是错的（正确答案被判成错答案）。

**三档分工**：

| 字段 | 判什么 | 进 `hit_rate` 分母 | 单独指标 |
|---|---|---|---|
| `must_contain` | **题面问到了、且答对了** | ✅ | — |
| `should_contain` | 题面**没问**，但答对了是加分 | ❌ | **深度率** `depth_rate` |
| `must_not_contain` | 负例命题 | — | 命中即幻觉 |

**深度率为什么单独报、不进总分**：它看的是「模型有没有主动多说一层」，
不是「模型有没有答到题」 —— 答多不等于答对，两者是不同的能力。
把它并进总分会让"话多"被当成"答得好"。

**`should_contain` 的准入有两条**：
① **题面没问**（否则它是 `must_contain`）；
② **支撑素材在该题 top-5 里**（否则它测的是检索，不是深度）。

> ⚠️ 第 ② 条最容易漏。模型**只能看到 top-5**（`agent/tools/rag_tool.py:62` 的 `top_k=5`，
> 和召回检查用的是同一个参数）——
> 一条深度项的素材不在 top-5 里，模型**根本答不出来**，
> 留着它，`depth_rate` 就从「模型有没有多说一层」退化成「检索有没有多给一块」。
>
> 【实测 2026-11-27】A04 按第 ② 条**砍掉 3 条**（5 条 → 2 条）：
> 「不写死集合名 → 要改代码+改配置+重启」（`项目速览.md:177`）、
> 「P3-10 切 alias 前没 flush」（`项目速览.md:201-202`、`术语表.md:47`）、
> 「零停机 ≠ 零延迟」（`项目优化.md:816`）——
> 三条在语料里都有，**只是这条问法的 top-5 拿不到**。
> 要考它们得**换问法**或**加大 `top_k`**，不是塞进答案键。

**分母**：A/B 组 8 题的 `should_contain` 共 **6 条**
（A01=1、A02=1、A04=2、B04=2，其余 0）。
`hit_rate` 的分母是 `must_contain` 共 **24 条**
（A01=3、A02=2、A03=3、A04=3、B01=4、B02=3、B03=3、B04=3）。

**降级的 3 处**（题面一个字没动）：

| 题 | 从 `must_contain` 降级的内容 | 降级理由 |
|---|---|---|
| A02 | 「最坏 32 步撞 LangGraph 默认 25 → `GraphRecursionError`」 | 题面问「是多少」「是不是写死的」，没问"为什么需要它" |
| B04 | 「`reflection_count` 永不重置」 | 题面问**上限**，不是**重置策略** |
| B04 | 「约定『返回 0 表示重置』；纯累加 reducer 写 0 清不掉」 | 题面问 reducer 的**性质**，不是**约定** |

> **为什么不能直接删掉这 3 条**：它们都是**这个项目的真知识**，删了可惜；
> 扩题面又会把答案写进题面（B04 变成「重置是怎么做的」→ 违反 R2「只带定位词，不带答案词」）。
> **降级是唯一两头都不亏的做法**。

### 6.1.1 两层尺子在判分时怎么落地

§1.1 分了两层，但**判分器看到的仍然是一份扁平的 `must_contain` 列表** —— 不告诉它哪条属于哪层。
落地方式：

| 层 | 判分器拿什么当"标准" | 答案键里写的是什么 |
|---|---|---|
| 锚点层 | **真相**（YAML / 代码里的真值） | 命题里带**正确的那个值**（例："chunk_size = 300"） |
| 其余 | 检索到的素材 | 命题直接复述素材里的事实 |

**关键点：锚点层的答案键必须是「真相」写出来的，不能抄语料。**
如果语料里那行写错了（`chunk_size` 被改成 500），答案键仍然是 300 ——
模型答 500 就判不命中。**这正是两层尺子相比单一忠实性尺子多出来的那一格信号。**

> 判分器不需要知道分层（保持盲评，§2.2 第 1 条）——
> 它只需要拿"问题 + 答案 + 答案键"判断语义等价。
> 分层是**我们出题时**的纪律，不是**判分时**的规则。

**答案键的真相来源**（写题时必须核对这些文件，**不能抄语料**）：

| 常量 | 真相在哪儿 | 【实测】2026-11-27 的真值 |
|---|---|---|
| `chunk_size` / `chunk_overlap` | `configs/model_config.yaml:106-107`（`EMBEDDING_CONFIG.text_splitter`） | `300` / `30` |
| 嵌入模型名 | `configs/model_config.yaml:12`（`DEFAULT_EMBEDDING_MODEL.model_name`） | `bge-m3:latest` |
| 向量维度 | `configs/model_config.yaml:57`（`PLATFORMS.ollama.embedding["bge-m3:latest"].dimensions`） | `1024` |
| `MAX_ITER` | `configs/agent_config.yaml:5` → `agent/constants.py:16` | `3` |
| `MAX_REFL` | `configs/agent_config.yaml:7` → `agent/constants.py:17` | `3` |
| `timeout.{llm,tool,total}` | `configs/agent_config.yaml:9-11` | `30` / `30` / `90` |
| `RECURSION_LIMIT` | `agent/runtime.py:25`（`_STEPS_PER_ROUND * (MAX_REFL+1) + 10` = `8×4+10`） | `42` |

> `chunk_size` / `chunk_overlap` 那两行 YAML 里自带一句警告
> （`model_config.yaml:102-104`：「这一段是切分参数的**唯一事实来源** … 以前代码写死 300、这里写 280，
> 而这份 YAML 从没被读过 → 改配置不生效」）——
> **正因为它曾经不生效，抄语料尤其危险**：语料可能记录着一个从未真正生效过的值。

### 6.2 阈值与权重

```
单题得分 score_i = 0.6 × hit_rate_i + 0.3 × (1 − halluc_i) + 0.1 × retrieval_hit_i
                   （D 组：不含 retrieval_hit，权重在剩余两项内归一化）

⚠️ 闸门（gate）：halluc_i = 1 → 该题直接判「不合格」，score_i 封顶 0.5
   理由：幻觉率跨题稀释，12 题错 1 题幻觉率仅 8.3%，
        纯权重公式会让一个胡编的答案拿到 0.975 分。
        闸门负责「不漏」，权重负责「排序」。

总均分 = mean(score_i)  —— 只用于简历上一句话；诊断必须看三个分项。

depth_rate（深度率）不进 score_i —— 单独报（§6.1.0）。
```

**闸门只对幻觉开，不对检索开** —— 即 R5：检索差是检索的锅，不该由生成背。

> ⚠️ **`hit_rate` 的分母是 24 条、不是 24 题**（A/B 组 8 题，条数不等）。
> 一处答案键超纲 = `hit_rate` 丢 1/24 = 0.042 → 总分丢 0.042 × 0.6 = **0.025**。
> 量级不大，但性质是错的 —— 这就是为什么要把超纲项降级（§6.1.0）。

### 6.3 归因分离表（报告必须有这一栏）

| 现象 | 归因 | 责任方 |
|---|---|---|
| 检索没召回 + 答案声明"没找到" | ✅ 系统行为正确 | 无责任（诚实性通过） |
| 检索没召回 + 答案编了内容 | 生成端幻觉 | **生成端** |
| 检索召回了 + 答案与素材矛盾 | 生成端不忠实 | **生成端** |
| 检索召回了 + 答案忠实 + 但素材本身是占位数据 | 工具侧 | **工具侧**（占位实现），不是模型的错 |
| 闭卷答对 | 该题剔除（R7） | 语料选型问题 |
| 检索召回了 + 答案对 + 但**块数/耗时这类语料数字变了** | 语料漂移 | **评测集设计**（→ 决策 4：只锚常量） |

### 6.4 复算要求（写进每份结果快照）

```
- 语料 SHA256（txt/*.txt 全部文件的 hash 清单）+ git commit
- 判分器模型名（MiniMax-M2.5）+ rubric 版本号
- 执行体模型名（MiniMax-M3.1-Flash）
- 被测问题集 hash
- 快照文件名带日期，永不覆盖
```

> **语料漂移是这套设计最大的不确定性** —— `docs/status/` 天天变（§4.5 已放弃冻结副本）。
> SHA256 + 日期快照是唯一兜底：**两份快照的语料 hash 不同，就不能直接比数字**。

### 6.5 闭卷对照 → 改成「先验可猜」准入探针（【实测】2026-11-27 已改）

**原方案（已废弃）**：每轮评测配一次闭卷对照 —— 同样的问题，**不给检索**（工具被禁用或素材预置为空）再跑一遍；
`闭卷得分 ≥ 带检索得分` → 该题剔除（R7）。

**为什么废弃**（两条实测理由，不是意见分歧）：

1. **"工具被禁用"这个形式测不到东西**。`agent/prompts/iter_prompt.py:17` 把「调用 rag_search」
   写死在决策规则里 → 工具禁掉以后模型**仍然发出工具调用**，ToolNode 回一句
   「rag_search is not a valid tool」，synth 节点于是产出
   **「工具调用异常」/「未在文档中找到」/「直接用通用知识作答」三种完全不同的输出**。
   → 它测的是"工具失败时模型诚实吗"，不是"这题能不能不查就答对"。**形态和目的对不上。**
2. **语料不存在污染**。评测语料是本项目 `txt/` 下的**本地文档**，从未被任何模型训练过（§4.1）。
   "闭卷也能答对"只可能来自模型的**通用先验**，不可能来自"模型背过我们的文档"。
   → 要防的不是污染，是**先验可猜**。

**改成的形式**：**一次性准入探针**（不是每轮评测的腿 ——
闭卷能力是**题目的属性**，同一道题在不同时刻的先验可猜性不会变，跑一次就够）。

裸问模型（**无 Agent、无工具、无项目上下文**），系统提示只给「请如实回答下面的问题。」，
再用**同一个判分器**按同一份答案键打分 → 闭卷 `hit_rate`：

| 题 | 裸问结果 | 真值 | 判读 |
|---|---|---|---|
| A01 | 明说"无法可靠确认具体数值，也不能仅凭常见配置猜测" | 300 / 30 / bge-m3 1024 | 先验**不可猜** ✅ |
| A02 | 答 **25**（LangGraph 默认值） | 42（由 MAX_ITER/MAX_REFL 推导） | 猜错 ✅ |

## §7 线 B —— 反思消融设计

### 7.1 真值表（**按坏答案的类型逐类定期望**）

> 早期版本这里是一张 2×2 表（好/坏 × 给素材/不给素材），把"坏答案"当成一类。
> 这掩盖了一件事：**不同类型的坏答案，在"没素材"时能不能判出来是不一样的。**

| 候选答案 | 标准素材 | 无关素材 | 测什么 |
|---|---|---|---|
| **good-1**（不带引用） | `end` ✅ | `end` ✅ | 假阳性（最危险的一类） |
| **good-2**（带引用） | `end` ✅ | `end` ✅ | 假阳性 + **引用维度对照** |
| **bad-1**（矛盾型） | `rewrite` ✅ | `end` ⚪ | 一致性判别力 / **信息边界** |
| **bad-2**（缺项型） | `rewrite` ✅ | `rewrite` ✅ | 完整性判别力（对题干也成立） |
| **bad-3**（答非所问型） | `rewrite` ✅ | `rewrite` ✅ | 完整性判别力（对题干也成立） |
| **bad-4**（编造型） | `end` ⚪ | `end` ⚪ | **结构性盲区**（素材沉默 → 无从质疑） |

图例：✅ = 期望判定；⚪ = **不可判定**（既不算真阳性也不算假阳性，计入"不可判定率"）。

**为什么 ①④ 在没素材时判不出、②③ 却判得出**（这是这张表的核心，也是 2×2 表说不清的地方）：

| 类型 | 缺陷是"答案 vs 什么"的对比 | 有素材 | 无素材 |
|---|---|---|---|
| **① 矛盾型** | **答案 vs 素材** | 判得出 | **判不出** —— 没有素材，就没有可比对的另一方 |
| **② 缺项型** | **答案 vs 题干** | 判得出 | **判得出** —— 题干说"三层"而答案只给两层，这个对比不需要素材 |
| **③ 答非所问型** | **答案 vs 题干** | 判得出 | **判得出** —— 答的东西和问题对不上，跟有没有素材无关 |
| **④ 编造型** | **素材里根本没有这个事实域** | **判不出** | **判不出** —— 素材既不支持也不反对 |

- ① 判不出是**信息边界的必然结果，不是失职**。
- ④ 判不出是**结构性盲区**：素材里压根没有"监控告警""自动重试""会话持久化""热更新"这类事实域。
- ②③ 判得出，是因为**题干本身也是一条信息** —— reflect 拿到的 state 里有 `messages[0]`（问题），
  `reflect_node.py:97` 正是用它拼 prompt 的。

> **注意 ④ 在"有素材"时也判不出** —— 这跟 ① 不同：① 有素材就能判，④ 有素材也判不出
> （素材只是"沉默"，不是"反对"）。这正是"素材外编造是反思的结构性盲区"这条结论的证据。

### 7.2 4 类坏答案的构造规则（可复现，不靠临场发挥）

以 B01 为例，素材 = 三层超时两行：

| 类型 | 构造 | 期望（有素材） | 期望（无素材） | 测什么 |
|---|---|---|---|---|
| **① 矛盾型** | 把"单次动作超时"改成"LLM 调用超时"（与素材矛盾） | `rewrite` | `end`（不可判定） | 一致性判别力 |
| **② 缺项型** | 删掉"整图 deadline"那一层，只答两层 | `rewrite` | `rewrite` | 完整性判别力 |
| **③ 答非所问型** | 换成 A01 的答案（答的是切块参数和维度） | `rewrite` | `rewrite` | 完整性判别力 |
| **④ 素材外编造型** | 加一句"超时还接了 Prometheus 监控告警"（素材里**根本没有**监控这个事实域） | **`end`（它判不出来）** | **`end`（它判不出来）** | **结构性盲区** |

> ⚠️ **④ 的定义在这一版被纠正过**（原 §7.2 写的是"加一句『超时上限是 30 秒』（素材说 90 s）"）：
> 那句话是**矛盾**（素材说的是 90），属于类型 ①，**不是**编造。
> 类型 ④ 的正确定义：**答案加了一个素材完全沉默的事实** ——
> 素材既没说它对，也没说它错，反思节点无从质疑。
> 混淆 ① 和 ④ 会让"不可判定率"这个指标算错。

**类型 ①④ 的处理**：计入**"不可判定率"** —— 既不算真阳性也不算假阳性。
这不是反思节点失职，是**信息边界的必然结果**（`reflect_prompt.py:44` 的判断维度是"与素材一致"，
素材本身没有的东西它无从质疑）。

> 这正是"占位数据怎么判断"的答案：**判断不了**。
> 而这个"判断不了"本身就是面试可讲的诚实边界 —— 反思节点在信息边界内有效，超出边界无能为力，
> 所以项目用两层超时和双计数器兜底，而不是指望它兜住一切。

> **一处需要实测后特别标注的期望**：`B03-bad-1 + 无关素材` —— 答案说"key 用的是工具名"，
> 而**题干本身就问"为什么不能按工具名记"** —— 矛盾在**题干**层面也成立。
> 真值表记 `end`，但实测若判 `rewrite`，说明 **reflect 的判断依据不止素材，还包括题干** ——
> 这是有价值的发现，要记进报告，**不能当成"reflect 不合格"**。详见语料 §5.4。

### 7.3 反思的四个指标

| 指标 | 定义 | 期望 |
|---|---|---|
| 真阳性率 | **期望判 `rewrite` 的格子**里判对的比例（①×标准素材 / ②×两种 / ③×两种） | 越高越好 |
| **假阳性率** | 好答案（good-1 / good-2）被判 `rewrite` 的比例 | **越低越好**（误报 → 反思不停 → 烧 token） |
| 不可判定率 | **期望判 `end` 且不可判定**的格子（①×无关素材 / ④×两种）里判 `end` 的比例 | 记录为**已知边界**，不追求降低 |
| **改后改善率** | 判了 `rewrite` → synth 重写 → 重写后质量分比原来高多少 | **这个才是"反思有用"的证据** |

> 每题 12 个格子（6 答案 × 2 素材）的期望分布：
> **5 格期望 `rewrite`**（①×S、②×S、②×N、③×S、③×N）、
> **3 格期望不可判定**（①×N、④×S、④×N）、
> **4 格期望 `end` 且可判定**（good-1 / good-2 × 两种素材）。
>
> ⚠️ **那 3 格"不可判定"的正确答案是 `end`** —— 但它**不算真阴性**。
> 判 `end` 在这 3 格里是**唯一合理的输出**（素材沉默 → 无从质疑），
> 却不能拿去充"假阳性率低"的分子 —— 否则会把"反思边界"粉饰成"反思判断准确"。
> → 这 3 格**单独统计**，不进真阳性率也不进假阳性率。

> **不可判定率的口径变了**（原 §7.3 只算 ④）：按 §7.1 的逐类真值表，
> ①在**无素材**时同样不可判定 → 它也要计入不可判定率，否则真阳性率会被稀释。
> 但 ①在**有素材**时判 `rewrite` 是**期望值**，要计入真阳性。
> → **不可判定是按"类型 × 素材种类"逐格统计的，不是一个笼统的比率。**

> **改后改善率需要跑全图**（rewrite → synth → 再判分），线 B 的 48 个 reflect 注入用例本身
> 只产出 `next_action`，不含重写后的答案。→ 改后改善率作为**第二轮**单独跑，
> 复用第一轮的判定结果，不混进本轮的四个指标。

> **重复次数**：LLM 有随机性，单次采样不能当基线（同 §2.2 判分器防偏第 2 条的逻辑）。
> 每种坏答案**重复 3 遍**取众数，报告里同时给**单次分布**。
>
> ⚠️ **【实测 2026-11-27】本轮按设计跑满 3 遍**（48 格 × 3 遍 = 144 次判定，判分错误 0）。
> → **仍是有限次采样**，数字分「逐遍分布 / 跨遍均值+极差 / 逐格众数」三样报，**不能当稳定基线**。
>
> ⚠️ **【实测 2026-11-27】"无关素材"格的语义与真值表对不上** ——
> 面对明显不相关的素材，reflect 判的是 `re_iterate`（"素材不够 / 需要再查"，
> `reflect_prompt.py:53`），不是本节真值表预期的 `end`。

### 7.4 零改代码的技术路径

`agent/nodes/reflect_node.py:63` 签名是 `reflect_node(state: AgentState, llm=None)` —— **LLM 可注入**：

```python
state = {
  "messages": [
      HumanMessage(content=问题),                                          # ← 必须是 messages[0]
      ToolMessage(content=素材, name="rag_search", tool_call_id="call_test_1"),
      AIMessage(content=候选答案),
  ],
  "tool_status": {"call_test_1": {"tool": "rag_search", "status": "success",
                                  "code": "OK", "retryable": False}},
  "last_critique": "", "reflection_count": 0, "iter_count": 0,
}
action = reflect_node(state, llm=真实LLM.with_structured_output(ReflectOutput))
```

**messages 的顺序有讲究**（三个读取点各自依赖它）：

| 读取点 | 位置 | 依赖 |
|---|---|---|
| `question = state["messages"][0].content` | `reflect_node.py:97` | 题目必须在 **`messages[0]`** |
| `_extract_latest_answer()` = 最后一条 AIMessage | `reflect_node.py:98` / `:55-60` | 答案必须是**最后一条 AIMessage** |
| `collect_round_material()` = 最后一条 HumanMessage 之后的全部 ToolMessage | `reflect_node.py:100` / `material.py:15-33` | 素材必须**排在 HumanMessage 之后** |

→ `Human → Tool → AIMessage` 三行是唯一同时满足三条的布局。完整用例清单见语料 §2.2。

→ **测的是生产代码里那个 prompt 构造，`agent/` 一个字不改。**

### 7.5 线 B 的题目设计

> **完整定稿见 `docs/task/答案质量评估语料.md`** —— 8 份素材、24 份候选答案、48 用例矩阵。
> 本节只记规模与分工。

| 项 | 值 |
|---|---|
| 题目 | 4 道（线 A 的 B 组：B01 / B02 / B03 / B04） |
| 素材 | 8 份 = 4 份**标准素材**（逐字取自语料，带 `file:line`）+ 4 份**无关素材**（同为真语料，但与题目无关） |
| 候选答案 | 24 份 = 每题 6 份（good-1 / good-2 / bad-1 矛盾 / bad-2 缺项 / bad-3 答非所问 / bad-4 编造） |
| 用例 | **48** = 4 题 × 6 答案 × 2 素材 |
| 重复 | 每例 3 遍取众数 → **144 次 reflect 调用** |

> **规模从 32 改成 48 的原因**：早期估"32 份"是把"6 份答案 × 2 份素材"当成"6 份"算了。
> 补齐后是 48 —— **每份候选答案都要配两种素材**，否则 §7.1 的真值表只测了一半。

**两条设计决定**：

1. **good-1 / good-2 成对**：两者内容完全相同，只差"是否标注引用"。
   `REFLECT_PROMPT` 的判断维度里有「引用：success 状态下是否标注引用？」——
   若 good-1（不标引用）被判 `rewrite`，那不是忠实性误报，是引用规则正常生效。
   → **成对设置，报告里就能把"忠实性误报"和"引用规则生效"分开**。
2. **无关素材的 `tool_status` 仍为 `success`**：不能改成 `empty` ——
   `REFLECT_PROMPT` 对 `empty` 有硬约束（不该判 `re_iterate`），
   改成 `empty` 会污染测量。详见语料 §2.3。

**注入点是生产代码的**：`reflect_node(state, llm=…)`，LLM 可注入 →
测的是**生产 prompt 原样**，零产品代码改动。

## §8 召回前提检查（新增方法论）

> **评估集的问法必须逐条过召回检查** —— 否则测的是"检索运气"，不是"答案质量"。

### 8.1 为什么必须做

【实测】同一个事实（A03 的三层超时秒数），**问法决定 top-5 能不能拿全**：

| 问法 | top-5 命中的数字 |
|---|---|
| "Agent 的三层超时分别设了多少秒？" | 只有 `30` —— **拿不到 90** |
| "三层超时机制的 llm、tool、total 分别是多少秒？" | `30` + `90` ✅ |
| "agent_config.yaml 里的 timeout 段配置是多少？" | `30` + `90` ✅ |
| "LLM 单次调用超时多少秒？工具超时多少秒？整图总时限多少秒？" | `30` + `90` ✅ |

原因：语料里 `90` 出现在**两处** —— `项目现状.md` 的 `timeout.{llm:30, tool:30, total:90}`
（配置段，整段一起进一个 chunk）和 `测试体系.md` 的 `TOTAL_TIMEOUT(90)`。
第一版问法排到的是讲"三层超时职责"的那块 chunk，**配置数字在隔壁 chunk**。

### 8.2 检查脚本

召回前提检查**并入正式评估脚本** `test/eval_quality/run_answer_quality_eval.py --recall-check`（下一步写）；
只读，走生产检索路径 `RagModel.retrieve()`，即线上 alias：

```
对每道题：
  1. 用生产路径检索 top-5
  2. 用**带上下文的正则**检查答案锚点是否出现在召回片段里
  3. 输出 锚点命中 k/n
```

### 12.3 线 B —— 反思消融

完整表格见 `docs/task/答案质量评估语料.md` §9（48 格 × 3 遍 = 144 次判定，判分错误 0）。
头条数字：

| 指标 | 均值 | 极差 | 口径 |
|---|---|---|---|
| **真阳性率** | **100%**（36/36） | **0.0** | 标准素材 × ①②③ 型坏答案 |
| **假阳性率** | **33.3%**（8/24） | 12.5 个百分点 | 标准素材 × 好答案；**忠实性误报 0/24** |
| **不可判定率** | **0%**（0/12） | 0.0 | ④ 编造型判 `end` 的比例（已知边界） |
| **`re_iterate` 异常** | **100%**（72/72） | 0.0 | 无关素材全部判「素材不够，要再查」 |
| **改后改善率** | **+0.2895**（19 格重写） | — | 合计净值；**真·坏答案 +0.5139（11/12 变好）**，**good-1 误伤 −0.1667** |

四条要分开讲的结论：
1. **忠实性判别力满分且零漂移** —— 36/36 三遍一致。
2. **假阳性全部来自「引用」规则** —— 8/8 的 critique 都明说"内容与素材一致"，
   都指向「success 状态下未标注引用」→ **忠实性误报 0/24**。
   good-1（不带引用）判 `rewrite` 8/12，good-2（带引用）判 `rewrite` **0/12**。
3. **"编造型是结构性盲区"的前提被推翻** —— ④×标准素材 **12/12 判 `rewrite`**。
4. **"反思有用"与"反思误伤"要分开报** —— 真·坏答案重写后平均 **+0.51**
   （11/12 变好，幻觉修好 3 例），但被误改的好答案平均 **−0.17**；
   合计 +0.29 是净值。

> ⚠️ **漂的是一格不是全局**：48 格里 47 格三遍判定完全一致；唯一翻转的是
> `B01-good-1-S`（`end`/`rewrite`/`rewrite`），假阳性率逐遍 25.0% → 37.5% → 37.5%
> 涨的就是这一格。
>
> ✅ **【实测】线 B 有复现性证据**：两次独立 3 遍跑**逐遍指标完全相同**、
> **48/48 格判定向量完全相同**，而 **144/144 格 critique 措辞都不同**
> （证明是独立采样，不是缓存）→ **线 B 的四个指标可以当稳定结论**。

# Dockerfile vs docker-compose.yml 区别与部署流程

## 一、Dockerfile vs docker-compose.yml

```
┌─────────────────────────────────────────────────────────────────┐
│                        Dockerfile                                │
│                                                                 │
│  用途：定义"如何构建"一个镜像                                     │
│  内容：基础系统 + 安装软件 + 复制代码 + 启动命令                    │
│                                                                 │
│  一句话：你是怎么做出这个蛋糕的？                                  │
│                                                                 │
│  示例：                                                           │
│  FROM python:3.11-slim          # 第1步：用什么操作系统             │
│  COPY requirements.txt .        # 第2步：复制依赖文件              │
│  RUN pip install -r ...         # 第3步：安装依赖                  │
│  COPY . .                       # 第4步：复制代码                  │
│  EXPOSE 8000                    # 第5步：声明端口                  │
│  CMD ["python", "main.py"]      # 第6步：启动命令                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                     docker-compose.yml                          │
│                                                                 │
│  用途：定义"如何运行"多个容器                                      │
│  内容：有哪些服务 + 端口映射 + 环境变量 + 数据卷 + 网络             │
│                                                                 │
│  一句话：这个蛋糕店需要哪些东西，怎么摆放？                        │
│                                                                 │
│  示例：                                                           │
│  services:                              # 有哪些服务              │
│    app:                                  #   服务1：你的应用        │
│      build: .                            #     从当前目录构建      │
│      ports: ["8000:8000"]                #     端口映射            │
│      depends_on: [milvus]                #     依赖 milvus         │
│    milvus:                               #   服务2：向量数据库     │
│      image: milvusdb/milvus:v2.6.16      #     用官方镜像          │
│      ports: ["19530:19530"]              #     端口映射            │
└─────────────────────────────────────────────────────────────────┘

核心区别：
┌────────────────┬────────────────────────────────────────────────┐
│    Dockerfile  │  描述"单个镜像"如何构建（怎么做事）             │
│   docker-compose│  描述"整个系统"如何运行（需要哪些服务）         │
└────────────────┴────────────────────────────────────────────────┘

比喻：
Dockerfile  =  菜谱（如何做这道菜）
docker-compose = 菜单（餐厅有哪些菜，怎么上菜）
```

## 二、你的项目中哪些是"可部署的服务"

```
┌─────────────────────────────────────────────────────────────────┐
│                     RAGMI 项目架构                               │
│                                                                 │
│  你当前运行的进程：                                               │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  1. Streamlit     python main_web.py    端口 8501        │   │
│  │  2. FastAPI       python main.py        端口 8000         │   │
│  │  3. Ollama        独立程序              端口 11434        │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
│  你当前运行的 Docker：                                           │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Milvus        容器 milvus-standalone    端口 19530       │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
│  不需要部署的：                                                   │
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │  Langchain    只是 Python 库，不是服务                      │   │
│  │  LLM          是 Ollama 提供的服务，已经运行中              │   │
│  │  Embedding    是 Ollama 提供的 bge-large 模型              │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

分类总结：

┌──────────────────────────────────────────────────────────────┐
│  需要部署的服务（用 Docker）                                   │
├──────────────────────────────────────────────────────────────┤
│  ✓ Milvus        → docker-compose 拉官方镜像                 │
│  ✓ Redis         → docker-compose 拉官方镜像（如果要加）     │
│  ✓ App (FastAPI) → 需要 Dockerfile 构建                     │
│  ✓ Streamlit     → 可以合并到 App 容器里                     │
│                                                              │
│  不是服务的依赖（直接安装的库）：                               │
├──────────────────────────────────────────────────────────────┤
│  ✗ Langchain     → pip install                               │
│  ✗ Pymilvus      → pip install                               │
│  ✗ LLM           → Ollama 独立运行（不是 Docker）            │
│  ✗ Embedding     → Ollama 独立运行（不是 Docker）            │
└──────────────────────────────────────────────────────────────┘

重要理解：
Ollama 不是在 Docker 里运行的，它是装在你宿主机上的独立程序。
代码通过 http://localhost:11434 访问 Ollama。
```

## 三、部署步骤的正确顺序

### 第 0 步：先搞清楚架构（最重要！）

```
在写任何代码之前，先回答：

1. 我要部署哪些服务？
   - Milvus（已有 Docker）
   - FastAPI（需要 Dockerfile）
   - Streamlit（可以合并到 App 容器）

2. 服务之间怎么通信？
   FastAPI → Milvus(:19530)
   Streamlit → FastAPI(:8000)

3. 哪些端口需要暴露给用户？
   用户 → :8501(Streamlit) → :8000(FastAPI)

4. 数据存哪里？
   Milvus 数据 → volume
   App 代码 → volume
```

### 第 1 步：先写 Dockerfile（构建你的应用镜像）

```
Dockerfile 定义的是"我怎么把这个 Python 应用变成镜像"

步骤：
a. 选择基础镜像（python:3.11-slim）
b. 安装系统依赖（curl 等）
c. 复制 requirements.txt
d. 安装 Python 依赖
e. 复制应用代码
f. 声明端口
g. 写启动命令

你的项目 Dockerfile 已经写好了：
FROM python:3.11-slim
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "api.api_file:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 第 2 步：写 docker-compose.yml（定义运行环境）

```
docker-compose.yml 定义的是"这个系统需要哪些服务，怎么运行"

步骤：
a. 定义服务（app, milvus, redis 等）
b. 配置每个服务的构建/镜像
c. 配置端口映射
d. 配置环境变量
e. 配置数据卷
f. 配置依赖关系

docker-compose 会：
1. 构建 app 镜像（用 Dockerfile）
2. 拉取 milvus 镜像
3. 启动所有容器
4. 配置网络互通
```

### 第 3 步：测试运行

```
命令：
docker-compose build      # 构建 app 镜像
docker-compose up -d       # 启动所有服务
docker ps                  # 查看运行状态
curl localhost:8000        # 测试 FastAPI
curl localhost:8501        # 测试 Streamlit
```

## 四、正确的思考顺序

```
┌─────────────────────────────────────────────────────────────────┐
│                     正确的思考顺序                               │
│                                                                 │
│  1. 先搞懂架构关系（第0步）                                      │
│     ↓                                                           │
│     我有哪些服务？服务之间怎么通信？                              │
│                                                                 │
│  2. 再搞懂端口关系（第0步）                                       │
│     ↓                                                           │
│     用户从哪个端口进来？服务之间用哪些端口？                       │
│     哪些需要暴露？哪些是内部使用？                                │
│                                                                 │
│  3. 再写 Dockerfile（第1步）                                     │
│     ↓                                                           │
│     你的 Python 应用怎么打包成镜像？                              │
│                                                                 │
│  4. 再写 docker-compose.yml（第2步）                            │
│     ↓                                                           │
│     所有服务怎么组织起来运行？                                    │
│                                                                 │
│  5. 最后测试端口连通性（第3步）                                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

错误顺序（会导致返工）：
❌ 先写 Dockerfile → 不知道服务怎么通信
❌ 先写 docker-compose → 不知道应用怎么构建
❌ 先搞端口 → 不知道服务关系，端口也是瞎配
```

## 五、实际例子：RAGMI 项目的部署

### 你现在的状态：

```
┌──────────────────────────────────────────────────────────┐
│  已部署（Docker）：                                       │
│  - Milvus 容器（milvus-standalone）                      │
│    端口 19530（gRPC）、9091（健康检查）                   │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│  未部署（手动运行）：                                     │
│  - FastAPI: python main.py → 端口 8000                  │
│  - Streamlit: streamlit run main_web.py → 端口 8501     │
│  - Ollama: 独立程序 → 端口 11434                        │
└──────────────────────────────────────────────────────────┘
```

### 要变成 Docker 部署，你需要：

```
第 1 步：写 Dockerfile
   → 把 FastAPI + Streamlit + 代码打包成镜像

第 2 步：写 docker-compose.yml
   → 把 app 容器 + milvus 容器 + 网络 + 端口 组织起来

第 3 步：运行
   → docker-compose up -d
```

## 一句话总结

```
Dockerfile  =  菜谱（描述单个应用怎么构建成镜像）
docker-compose = 菜单（描述整个系统有哪些服务，怎么运行）

架构关系  →  先搞懂（有哪些服务，怎么通信）
端口关系  →  再搞懂（哪些暴露，哪些内部）
Dockerfile →  然后写（你的应用怎么打包）
docker-compose →  最后写（服务怎么组织）
```

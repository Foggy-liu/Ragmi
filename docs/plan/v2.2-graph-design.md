## 0. 目标

把 v2.1 的 3 节点（agent / tools / reflect）重构为 v2.2 的 4 节点（iter / tools / synth / reflect），同时把单一 `iterations` 计数器拆为 3 个独立计数器（`iter_count` / `synth_count` / `reflection_count`），消除 v2.1 的 3 个 bug：

1. **节点层双角色 bug**：`agent_node` 同时承担"决定要不要调工具"和"写最终答案"两种 LLM 模式，互相干扰。
2. **counter 层混叠 bug**：`iterations` 一个计数器无法区分"agent_node 调用次数"，导致反思触发条件被短路。
3. **工具超时死循环 bug**：state 里没有"工具是否成功"信号，反思节点误判"还需再查"，陷入 `iter → tools(超时) → iter → tools(超时)` 死循环。

### 成功标准

- `agent/graph.py` 编译出 4 节点图（iter / tools / synth / reflect）。
- `AgentState` 含 6 字段：`messages` / `iter_count` / `synth_count` / `reflection_count` / `tool_status` / `last_critique`。
- `iter_node` 只挂 `bind_tools(ALL_TOOLS)`，prompt 强制"不调工具时输出 `READY` 信号，不写答案"。
- `synth_node` 不挂 `bind_tools`，根据 `tool_status` 和 `last_critique` 写答案（初始 + 重写共用同一节点）。
- `reflect_node` 输出 JSON `{is_sufficient, critique, next_action}`（LLM 输出字段名），写入 `state["last_critique"]`（state 字段名，避免与 messages 中的 critique 混淆），`next_action` 三选一 `end` / `rewrite` / `re_iterate`。
- `should_continue` 条件边根据 `last.tool_calls` 路由：有 → `tools`，没有 → `synth`（默认兜底）。
- `after_reflect` 条件边根据 `next_action` 路由：`end` → END，`rewrite` → `synth`，`re_iterate` → `iter`。
- `StatusToolNode(ToolNode)` 在工具成功 / 空 / 超时 / 异常时分别写 `tool_status` 字典。
- 工具清单从 1 个（`rag_search`）扩展为 4 个（`rag_search` / `calculator` / `weather` / `web_search`），`calculator` / `weather` / `web_search` 是占位实现。
- 所有节点统一用 `MiniMax-M3` LLM，反思 prompt 加"评审视角"约束。
- `pytest test/test_v22_*.py` 全绿，覆盖 3 个 v2.1 bug 的回归测试。

## 2. 架构与数据流

```
[用户问题 HumanMessage]
        │
        ▼
[iter 节点] ← LLM(M3).bind_tools(ALL_TOOLS)
   iter_count += 1
   输出 AIMessage：
     ├─ tool_calls=[...] → should_continue → tools
     └─ content="READY" → should_continue → synth
        │
        ▼
[tools 节点] ← LangGraph ToolNode(ALL_TOOLS) + 状态捕获
   StatusToolNode 写入 tool_status 字典
   无 LLM 调用
        │
        └────────── (回到 iter) ──────────┐
                                          │
        ┌──── synth 路径 ──────────────────┘
        │
        ▼
[synth 节点] ← LLM(M3)（不挂 bind_tools）
   synth_count += 1
   prompt 模式切换：
     ├─ 首次：基于素材写答案
     └─ 重写：基于素材 + last_critique 改写
        │
        ▼ (无条件边)
[reflect 节点] ← LLM(M3)
   reflection_count += 1
   输出 JSON：{is_sufficient, critique, next_action}
   rewrite / re_iterate 时重置 iter_count + synth_count = 0
        │
        ▼
[after_reflect 条件边]
   ├─ "end" → END
   ├─ "rewrite" → synth（synth_count 已重置，可再写 2 次）
   └─ "re_iterate" → iter（iter_count 已重置，可再调 3 次工具）
```

## 3. 状态 Schema

```python
# agent/state.py
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class AgentState(TypedDict):
    # LangChain messages，自带 add_messages reducer
    messages: Annotated[list, add_messages]

    # 3 个独立 counter（每节点一个，避免 counter 层混叠 v2.1 bug）
    iter_count: int        # iter 节点专用，上限 3，reflect 重置
    synth_count: int       # synth 节点专用，上限 2，reflect 重置
    reflection_count: int  # reflect 节点专用，上限 3，永久累加

    # 多工具状态字典
    tool_status: dict[str, str]  # {"rag_search": "success", "weather": "timeout", ...}

    # reflect 节点输出的反馈（synth 节点在重写模式时读取）
    # 写 state 而非 AIMessage 追加：避免污染消息历史；单字段不重复
    last_critique: str
```

## 4. 节点设计

### 4.1 iter 节点

**职责**：纯决策——"要不要调工具"。**不写答案**。不调工具时输出简短信号 `READY`，让 synth 节点写答案。

```python
# agent/nodes/iter_node.py
from agent.state import AgentState
from agent.tools import ALL_TOOLS
from langchain_core.messages import AIMessage, HumanMessage, ToolMessage

def iter_node(state: AgentState) -> dict:
    """纯决策节点，bind_tools(ALL_TOOLS)"""
    iter_count = (state.get("iter_count") or 0)

    # 边界：iter_count 触达上限强制输出 READY（让 should_continue → synth → END）
    if iter_count >= MAX_ITER:
        return {
            "messages": [AIMessage(content="已达迭代上限，结束")],
            "iter_count": iter_count + 1,
        }

    try:
        llm_with_tools = llm.bind_tools(ALL_TOOLS)
        prompt = build_iter_prompt(state)
        response = llm_with_tools.invoke(prompt)
    except Exception as e:
        # LLM 调用本身失败时返回 READY，让 synth 写兜底答案
        response = AIMessage(content="READY")  # 注意：兜底，不写答案

    return {
        "messages": [response],
        "iter_count": iter_count + 1,
    }
```

**prompt 关键约束**（`agent/prompts/iter_prompt.py`）：

```text
你是"是否需要查资料"决策节点。

【用户问题】
{question}

【当前状态】
- iter_count: {iter_count} / 3
- tool_status: {tool_status}
- 反思反馈（reflect 触发 re_iterate 时才有）: {last_critique}

【决策规则】
1. 用户问题涉及项目文档 / 库 API / 代码片段 → 调用 rag_search
2. 通用知识 / 寒暄 / 闲聊 → 不调用
3. 工具上次 timeout/error → 优先换个查询词；连续失败则不调用
4. 工具上次 empty → 换个查询词；连续空则不调用
5. iter_count ≥ 3 → 不再调工具

【输出】
- 调用工具：标准 Function Calling
- 不调用：输出 "READY"（让 synth 节点写答案）
- **不要写答案**——写答案是 synth 节点的工作
```

### 4.2 tools 节点

**职责**：实际调用工具 + 写入 `tool_status` 字典。

```python
# agent/nodes/status_tool_node.py
from langgraph.prebuilt import ToolNode
from agent.tools import ALL_TOOLS

class StatusToolNode(ToolNode):
    """包装 LangGraph ToolNode，捕获异常写 tool_status"""

    def __init__(self):
        super().__init__(ALL_TOOLS)

    def __call__(self, state: AgentState) -> dict:
        # 取最后一个 AIMessage 的 tool_calls
        last_msg = state["messages"][-1]
        if not (hasattr(last_msg, "tool_calls") and last_msg.tool_calls):
            return {}  # 没有 tool_calls 不应到这（兜底）
        tool_name = last_msg.tool_calls[0]["name"]

        try:
            result = super().__call__(state)
            # ToolNode 返回 ToolMessage 列表
            tool_msgs = result.get("messages", [])
            has_content = any(getattr(m, "content", "") for m in tool_msgs)
            status = "success" if has_content else "empty"
        except TimeoutError:
            status = "timeout"
            # 重新生成 ToolMessage 占位，避免 graph 卡住
            result = {"messages": [ToolMessage(content="查询超时", tool_call_id=last_msg.tool_calls[0]["id"])]}
        except Exception:
            status = "error"
            result = {"messages": [ToolMessage(content="工具异常", tool_call_id=last_msg.tool_calls[0]["id"])]}

        return {
            **result,
            "tool_status": {tool_name: status},
        }
```

### 4.3 synth 节点

**职责**：基于素材写最终答案。**单一节点处理初始 + 重写**（通过 `last_critique` 是否存在切换 prompt 模式）。

```python
# agent/nodes/synth_node.py
def synth_node(state: AgentState) -> dict:
    """综合节点，根据 state["last_critique"] 切换 prompt 模式（首次 vs 重写）"""
    try:
        prompt = build_synth_prompt(state)  # 内部判断首次 / 重写
        response = llm.invoke(prompt)
    except Exception as e:
        # LLM 调用本身失败时返回友好错误，避免 graph 崩溃
        response = AIMessage(content=f"综合答案生成失败：{type(e).__name__}")

    return {
        "messages": [response],
        "synth_count": (state.get("synth_count") or 0) + 1,
        # last_critique 透传（reflect 下次会更新）
        "last_critique": state.get("last_critique"),
    }
```

**prompt 关键约束**（`agent/prompts/synth_prompt.py`）：

```text
你是"基于已有素材写最终答案"综合节点。

【用户问题】
{question}

【可用素材】（如果有）
{chunks}

【工具状态】
{tool_status}

【反思反馈】（如果有——重写模式才有）
{last_critique}

【撰写规则】
1. 素材非空（success）→ 基于素材写答案 + 标注引用
2. 素材为空（empty）→ 诚实说明"未在文档中找到相关资料"
3. 工具超时（timeout）→ 诚实说明"查询受限，无法给出依据"
4. 工具异常（error）→ 诚实说明"工具调用异常"
5. 有 last_critique → 按反馈修正答案
6. 中文输出，结构清晰

【输出】
仅写答案文本，不调工具。
```

### 4.4 reflect 节点

**职责**：评审答案 + 决定 `next_action`。

```python
# agent/nodes/reflect_node.py
from pydantic import BaseModel, Field
from typing import Literal

class ReflectOutput(BaseModel):
    """Structured output for reflect node"""
    is_sufficient: bool
    critique: str = ""
    next_action: Literal["end", "rewrite", "re_iterate"]

def reflect_node(state: AgentState) -> dict:
    """反思节点，输出 JSON {is_sufficient, critique, next_action}"""
    try:
        prompt = build_reflect_prompt(state)
        response = llm.with_structured_output(ReflectOutput).invoke(prompt)
        parsed = response.model_dump()
    except Exception as e:
        # LLM 调用失败 / JSON 解析失败 → 强制 rewrite（reflection_count 上限兜底防死循环）
        parsed = {"is_sufficient": False, "critique": "反思解析失败", "next_action": "rewrite"}

    action = parsed.get("next_action", "end")
    reflection_count = (state.get("reflection_count") or 0) + 1

    # 基础返回
    result = {
        "reflection_count": reflection_count,
        "next_action": action,
        "last_critique": parsed.get("critique", ""),
    }

    # rewrite / re_iterate 时重置 iter_count + synth_count
    if action != "end":
        result["iter_count"] = 0
        result["synth_count"] = 0

    # 边界：reflection_count 触达上限强制 end（防止死循环）
    if reflection_count >= MAX_REFL:
        result["next_action"] = "end"

    return result
```

**prompt 关键约束**（`agent/prompts/reflect_prompt.py`）：

```text
你是"评审答案质量"反思节点。

【用户问题】
{question}

【本次答案】
{latest_answer}

【工具状态】
{tool_status}

【历史反思】（本次会话内）
{previous_reflections}

【任务】
按 JSON 输出评分：

{
    "is_sufficient": bool,
    "critique": str,
    "next_action": "end" | "rewrite" | "re_iterate"
}

【判断维度】
- 正确性：答案与素材是否一致？有事实错误吗？
- 完整性：是否回答了用户所有问题？
- 诚实性：工具失败时是否如实声明？
- 引用：success 状态下是否标注引用？

【next_action 选择】
- end：答案好 → 结束
- rewrite：素材够用但写得不好 → 综合节点重写
- re_iterate：素材不够 / 需要再查 → 回迭代节点

【硬约束】
- 工具 timeout/error 时不应判 re_iterate（避免死循环）
- 仅输出 JSON，不解释

【角色约束】
你是评审者，不是答题者。不要为答案找借口，要像用户一样挑刺。
```

## 5. 条件边函数

### 5.1 `should_continue`

```python
# agent/nodes/should_continue.py
def should_continue(state: AgentState) -> str:
    """iter → tools | iter → synth 路由"""
    last = state["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        return "tools"
    return "synth"  # 默认兜底（含 LLM 乱码、iter 输出 READY）
```

### 5.2 `after_reflect`

```python
# agent/nodes/should_continue.py
def after_reflect(state: AgentState) -> str:
    """reflect → END | synth | iter 路由"""
    action = state.get("next_action", "end")
    if action == "end":
        return END
    elif action == "rewrite":
        return "synth"
    elif action == "re_iterate":
        return "iter"
    return END  # 兜底
```

### 6.2 `tool_status` 的 4 种值

| 值 | 触发条件 | 反思应如何理解 |
|---|---|---|
| `"success"` | ToolNode 返回至少一条 chunk | 答案应基于素材；评"答案与素材是否一致" |
| `"empty"` | ToolNode 返回 `[]` / 空字符串（无超时） | "查无此资料"是事实；评"是否承认无资料" |
| `"timeout"` | ToolNode 抛 `TimeoutError` | 这是工具故障；评"是否如实说明查询受限"，**不应判 re_iterate** |
| `"error"` | 工具崩溃等其他异常 | 同 `timeout`，但 last_critique 更通用 |

## 7. Graph 构建

```python
# agent/graph.py
from langgraph.graph import StateGraph, START, END
from agent.state import AgentState
from agent.nodes.iter_node import iter_node
from agent.nodes.synth_node import synth_node
from agent.nodes.reflect_node import reflect_node
from agent.nodes.status_tool_node import StatusToolNode
from agent.nodes.should_continue import should_continue, after_reflect
# MAX_ITER / MAX_SYNTH / MAX_REFL 来自 configs/agent_config.yaml（见第 8 节）

def build_graph():
    graph = StateGraph(AgentState)

    graph.add_node("iter", iter_node)
    graph.add_node("tools", StatusToolNode())
    graph.add_node("synth", synth_node)
    graph.add_node("reflect", reflect_node)

    # START → iter（无条件）
    graph.add_edge(START, "iter")

    # iter → tools | iter → synth（条件边）
    graph.add_conditional_edges(
        "iter",
        should_continue,
        {"tools": "tools", "synth": "synth"},
    )

    # tools → iter（无条件）
    graph.add_edge("tools", "iter")

    # synth → reflect（无条件）
    graph.add_edge("synth", "reflect")

    # reflect → END | synth | iter（条件边）
    graph.add_conditional_edges(
        "reflect",
        after_reflect,
        {"end": END, "rewrite": "synth", "re_iterate": "iter"},
    )

    return graph.compile()
```

加载代码：

| Counter | 默认上限 | 重置时机 |
|---|---|---|
| `iter_count` | `MAX_ITER = 3`（config） | reflect 触发 `"rewrite"` 或 `"re_iterate"` 后重置为 0 |
| `synth_count` | `MAX_SYNTH = 2`（config） | reflect 触发 `"rewrite"` 或 `"re_iterate"` 后重置为 0 |
| `reflection_count` | `MAX_REFL = 3`（config） | 永不重置（绝对上限） |

### 8.1 最坏路径分析

```
Cycle 1: iter 3 + synth 1 + refl 1 = 5 LLM → refl (rewrite)
  ↓ reflect 重置 iter_count, synth_count
Cycle 2: iter 3 + synth 1 + refl 1 = 5 LLM → refl (rewrite)
  ↓ reflect 重置
Cycle 3: iter 3 + synth 1 + refl 1 = 5 LLM → refl (end)

总计：iter 9 + synth 3 + refl 3 = 15 LLM
```

### 8.2 实际路径（评估 92% 一次过）

```
iter 1 + synth 1 + refl 1 = 3 LLM
```

## 9. 边界与兜底（4 条护栏）

| 场景 | 处理 | 实现位置 |
|---|---|---|
| iter_count > 3 或 synth_count > 2 | 强制 END，输出 `latest_answer` | `iter_node` / `synth_node` 入口检查 |
| reflect 收到空答案 | 强制 `rewrite`，critique = "答案为空" | `reflect_node` 的 JSON 解析 fallback |
| iter 不调工具 | 输出 `READY` 信号（不写答案） | iter prompt + should_continue 默认走 synth |
| 条件边 AIMessage 乱码 | 默认走 synth（兜底） | `should_continue` 没有 `tool_calls` → `synth` |

### 9.1 Counter 超限的强制 END 实现

```python
# agent/nodes/iter_node.py（修改）
def iter_node(state: AgentState) -> dict:
    iter_count = state.get("iter_count") or 0
    if iter_count >= MAX_ITER:
        # 强制输出一个空 AIMessage，让 should_continue 走 synth（兜底）
        return {"messages": [AIMessage(content="已达迭代上限，结束")]}

    # ... 正常路径
```

类似处理 `synth_count > 2`。

## 13. 风险与权衡

### 13.1 已知风险

| 风险 | 缓解 |
|---|---|
| **多工具 dict 顺序依赖**：`StatusToolNode` 只看最后 tool_calls 的第一个 name，多个并行工具调用时可能丢失状态 | 暂不支持并行工具（v2.2 限定串行调用）；后续 spec 处理 |
| **`tool_status` 写入与 read 顺序**：iter 节点读 `tool_status` 时，tools 节点的写入必须已经发生 | LangGraph 默认顺序边确保：`tools → iter` 是无条件边，状态自动 commit |
| **LLM 调用本身抛异常**：`llm.invoke()` 失败时图崩溃 | iter / synth / reflect 节点已加 `try/except`，返回友好错误或兜底信号 |
| **`ReflectOutput` Pydantic 解析失败**：LLM 输出格式错误 | `except` 兜底 → `{is_sufficient=False, next_action="rewrite"}`；reflection_count 上限防死循环 |
| **占位工具的 LLM 误用**：calculator / weather 占位实现可能被 LLM 滥用 | v2.2 暂不限制；后续 spec 加 tool 白名单 / 配额 |
| **MAX_* 配置错误**：YAML 误填大数字 | 默认值兜底；plan 中加启动时 assert 检查 |

### 13.2 与 v2.1 的兼容性

- `api/api_agent.py` 不变（仍返回 `response` 字符串）。
- `agent.runtime.ask()` 非 debug 模式返回值不变。
- v2.1 测试（`test/test_reflect.py` / `test/test_reflection_count.py`）**全部废弃**，按 v2.2 spec 重写新测试文件（`test_v22_*.py`）。

### 13.3 不在范围内（后续 spec）

- 多轮记忆（LangGraph `MemorySaver` / `PostgresSaver`）；
- 工具并行调用（`StatusToolNode` 当前只支持串行）；
- 反思 prompt 的 fine-tuning；
- 流式输出（SSE）；
- token 预算控制（区别于 counter，按 token 计算）；
- 替换 M3 为更大模型或不同 judge 模型；
- Prompt 版本化（Git 管理 + A/B 测试基础设施）；
- LangSmith / 日志可观察性集成。

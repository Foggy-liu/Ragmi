## §2 各层具体测什么

### 2.1 L2 · Agent 流程（主角，17 条独立 + 9 参数化 = 26 收集项）

用**假 LLM**（剧本控制每次返回什么）+ **假检索**（控制返回内容/空/超时/报错），跑**真的 LangGraph 图**。

| 编号 | 测什么 |
|---|---|
| F1 | 工具成功 → 状态 `success`/`OK`，ToolMessage 是拼接后的原文（未被包装） |
| **F1c** | **检索到的资料真的进了综合节点的 prompt**（grounding —— 防"答案非空"恒真） |
| F1b | 同一轮调两次同一工具 → `tool_status` 的 key **等于调用 id**，两条不互相覆盖 |
| F2 | 检索为空 → 状态 `empty`/`EMPTY_RESULT`，ToolMessage 是**空串**（不是中文兜底） |
| F3 | **工具超时** → 状态 `timeout`/`TOOL_TIMEOUT`/`retryable=true`，ToolMessage 是结构化 JSON，图不崩 |
| F4 | **工具失败** → 状态 `error`/`TOOL_ERROR`/`retryable=false`，同上 |
| **F4b** | **检索失败 ≠ 检索为空** → `RetrievalError` 必须记成 `error`，不是 `empty`（**P2-7**） |
| F5 | iter 的 LLM 崩 → 兜底 `"READY"` → synth 仍出答案 |
| F6 | reflect 崩 → 兜底 `rewrite` + `critique="反思解析失败"`，靠 `MAX_REFL` 收手 |
| F7 | **死循环防护** → reflect 恒判 `re_iterate` → 节点进 4 次、LLM 只调 3 次 |
| F8 | **工具循环上限** → iter 恒发 tool_calls → 节点进 3 次、LLM 只调 2 次，无悬空 |
| F9a/b/c | **三种超时时机**（进门即过期 / 答前过期 / 反思时过期），行为各不相同 |
| F9a_x | **超时兜底不交内部占位** —— 答案不能是「已达总时限，停止思考」 |
| F10 | reflect 返回未知 action → 兜底走 `__end__` |
| F11 | `ask()` 返回**恰好 5 个键**，且答案**不是任何内部占位** |

> **公共不变式**（参数化套在 F1–F10 上）：每个 `tool_call` 都有对应 `ToolMessage` —— **悬空数 == 0**。
> 这是 v2.2 修过的 bug（悬空让 MiniMax 报 HTTP 400）的回归护栏。

### 2.6 L2 · 工具纯函数（26 条，永远跑）

`test/test_tools.py` —— 测 `calculator` 的**求值逻辑**（绕开 LangChain 的参数解析，直接调工具本体）
+ `rag_search` 的**异常归一化**。
**P1-2 的回归护栏**：`calculator` 原来写的是 `str(eval(expression))`，
**直接执行 LLM 传来的字符串** → RCE。

| 组 | 测什么 |
|---|---|
| 算术（8 条） | 加减乘除、优先级、括号、浮点除、幂、取模、一元负号、前后空白 |
| 危险输入（10 条） | `__import__('os').system(...)`、`open(...).read()`、`().__class__`、字符串常量、`True + 1`、`x + 1`、`2**100000`、200 项长表达式、`1/0`、`2 +` |
| 畸形输入（4 条，参数化） | `""` / `"   "` / `"()"` / `"1+"` → 返回 `ERROR: ...` 字符串而**不是抛异常** |
| 检索异常归一化（4 条） | `RetrievalError` → `AgentToolError`；`RetrievalError`（底层是超时）→ `AgentTimeoutError`；第三方异常 → `AgentToolError`；**检索为空 → 返回空串（不是异常）** |

> 关键细节：`bool` 是 `int` 的子类 → `True + 1` 必须显式拒绝；
> `ast.parse` **不吃前导空白**（报 `IndentationError`）而 `eval` 吃 → 求值前必须 `.strip()`。

### 2.7 L2 · RAG 检索语义（7 条，永远跑）

`test/test_rag_model.py` —— 测 `core/rags/rags.py` 最重要的一条契约：
**「检索失败」和「检索到 0 条」必须可区分**（**P2-7**）。

| 编号 | 测什么 |
|---|---|
| R-1 | 向量库没连上 → 抛 `RetrievalError`（**不是**返回 `[]`） |
| R-2 | 查询报错 → 抛 `RetrievalError`，且保留原始异常作 `__cause__`（工具层靠它判超时） |
| R-3 | embedding 客户端报错（超时等）→ 也是 `RetrievalError` |
| R-4 | 检索到 0 条 → 返回 `[]`，**不抛异常** |
| R-5 | 正常路径 → 返回 chunk 文本列表 |
| R-6 | `/rag` 直连链路：检索失败**仍然返回 200**（吞异常，按无上下文处理） |
| R-7 | 检索失败时给模型的上下文是「没有找到相关文档片段」 |

## §3 "假"的部分怎么造

| 假的 | 怎么假 | **真的保留了什么** |
|---|---|---|
| **LLM** | 替换 `LLMmodel.create_minimax()`，返回一个按剧本说话的假对象 | think 剥离（`ThinkingStripRunnable`）、节点逻辑、路由图、计数器 reducer 全是真的 |
| **检索** | 只替换 `agent.tools.rag_tool._ensure_rag`（工具**底下那一层**） | `Timer` 计时、异常归一化（`RuntimeError`→`AgentToolError`）、`status_wrapper` 4 态分类、ToolMessage 写入 全是真的 |
| **后端**（浏览器层） | conftest 起一个本地假 HTTP 服务，前端经 `API_BASE_URL` 指过去 | Streamlit 页面渲染、前端字段读取、Streamlit 状态机 全是真的 |

### 3.1 关键：为什么不能换掉整个工具

换掉工具 = 把 `Timer`、异常归一化、`status_wrapper` 这三段**最该被测的代码**排除在测试之外 —— 等于什么都没测。

### 3.2 关键：为什么不能只测节点不测图

只测节点 = 测不到路由。而"流程走不走得通"正是本轮的核心目标。

## §4 必须先知道的几件事（实测得出）

| # | 事实 | 影响 |
|---|---|---|
| 1 | **三个页面的后端调用都发生在 Streamlit 服务端进程里**（`requests.post`），不在浏览器 | Playwright 的 `page.route()` **拦不到** → 必须用"进程外假后端" |
| 2 | 前端 API 地址**三处写死**（`localhost:8000` / `api:8000` / 裸 URL） | 知识库问答页与仓库管理页在本地**连不上后端**（实测 `Failed to resolve 'api'`）；**必须先改成读环境变量** |
| 3 | `import main` 要 **5.1 秒**（冷启动 .pyc 时 12.5 秒）；`import agent.runtime` **3.5 秒** | 快回归的验收线是 **< 60 秒**，不是 30 秒 |
| 4 | `main.py:63` 在**模块级**调 `LLMmodel.create_minimax()` | 假 LLM 的 patch 若在 `import main` **之后**生效 → `main` 的默认模型变假件 → **实测直接 `AttributeError` 崩掉**。所以 `import main` 必须在测试模块**顶层**（collection 期）完成 |
| 5 | `add_messages` 按 `message.id` 去重 | 假件**复用同一个 AIMessage 对象**会被当成"更新"而不是"新增" → 必须每次返回**全新副本** |
| 6 | `runtime.py:95` 写死 `deadline = now + TOTAL_TIMEOUT(90)` | 超时类用例（F9）**不能**用 `ask()`，必须直接 `graph.invoke()` 自己传 `deadline` |
| 7 | `api/api_agent.py:18` 的 `Field(...)` **没有** `min_length` | 空 query 是 **200** 不是 422 |
| 8 | **Streamlit 把每个 `st.button` 渲染两次**（一次在底部固定容器可见、一次在主区隐藏） | `button:has-text("🗑")` 会撞 Playwright **strict mode** → 必须 `.first` |
| 9 | **`st.title` / `st.subheader` / `st.header` 都是 `data-testid="stHeading"`** | 一页可能有多个 heading → 断言要 `.first`（`st.title` 在前） |
| 10 | **sac.menu 渲染在 iframe 里**，src 实测是 `/component/streamlit_antd_components.utils.component_func.sac/index.html` | 设计文档假设的 `/component/sac.<hash>/index.html` **永远匹配不上** → 只按 `"/component/" in url and "sac" in url` 匹配 |
| 11 | 前端上传会带 query string（`?overwrite=False`） | 假后端路由匹配必须**先剥掉 `?...`**，否则 `/api/batch-upload-and-parse` 一律落进 404 |
| 12 | `playwright 1.58.0` 钉的是 **chromium build 1208** | `install chromium` **只装 full chromium**，headless shell 要**单独装**（`install chromium-headless-shell`），否则报 `Executable doesn't exist` |
| 13 | **Milvus 的 `insert()` 是异步落盘的** —— 返回只代表 WAL 接收成功，segment 还没 flush | 在 `insert → create_index → load_collection → alter_alias` 走完的**瞬间** `query()` 仍可能返回 **0 行**。实测 1667 行时命中（2026-11-16 全量跑挂在这），3 行对照实验里延迟为 0 → **窗口大小跟数据量有关**。所以断言必须**轮询**而不是查一次 |
| 14 | **跑着的 Streamlit 进程可能还是改代码之前的老版本** | 老进程里 `web_page/rag_direct_page.py` / `repo_admin.py` 还写死 `API_BASE = "http://api:8000"` → 知识库问答页与仓库管理页直接报 `NameResolutionError: Failed to resolve 'api'`。**改了前端代码必须重启 Streamlit**，否则测的是旧代码（2026-11-17 真栈体检踩到：重启后 2 个失败 → 0 个失败） |
| 15 | **切页后必须等标题变了再碰输入框** | 切页那一瞬**旧页面的输入框还在 DOM 里** → `wait_for_selector(CHAT_INPUT)` 立刻返回，`fill()` 就打在被拆掉的旧元素上，消息永远发不出去（页面上 0 条消息）。**等 heading 变化**（E6 的写法）才会自动等掉渲染延迟 |

## §7 跑法

```bash
pytest -m "not slow and not e2e" -v   # 快回归（秒级）
pytest -m e2e -v --tracing=retain-on-failure   # 浏览器
pytest -m slow -v                    # 真环境（花钱、慢）
pytest -v                            # 全量

# 真栈全接口体检（非 pytest；需真服务全在位；会开可见 Chrome、花钱）
PYTHONIOENCODING=utf-8 python test/e2e/real_stack_check.py
```

> ⚠️ **`-m` 是"或"语义** —— E8 同时带 `slow` 和 `e2e` 两个标记，
> 所以 `pytest -m slow` 也会选它，`pytest -m e2e` 也会选它。
>
> ⚠️ **Playwright 前置**：`python -m playwright install chromium` **只装 full chromium**，
> headless shell 要单独装：`python -m playwright install chromium-headless-shell`。
> 临时兜底：`pytest -m e2e --browser-channel=chromium`。

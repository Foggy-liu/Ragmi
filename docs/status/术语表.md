# 术语表 —— RAGMI 项目

> **这是什么**：本项目里出现的**框架术语 + 本项目自有说法**的对照表。
> 每条给出：官方原名 → 中文 → 一句话作用 → 本项目落在哪个文件哪一行 → 本项目怎么用。
>
> **怎么用**：看到不认识的词 → 翻这张表 → 顺着 `file:line` 去看源码。
> 概念本身怎么运作，看 [`项目速览.md`](./项目速览.md) §1（只展开真正需要理解的那部分）。
>
> **术语来源纪律**：本表里的中文括注一律是**框架官方中文**或**仓库里已有的原话**
> （代码注释 / docstring / `docs/status/` 既有说法）。没有自造标签。
> 引入本表时专门纠正过一次自造说法——
> "单例化依赖" → 项目原话是 **`app 级单例` / app-level singleton**；
> "原子 alias 切换" → 项目原话是 **`原子切换 alias`**（`vector_main.py` 的注释原句）。

## 栏 1 · LangGraph / LangChain

| 术语 | 一句话作用 | 位置 | 本项目怎么用 |
|---|---|---|---|
| `StateGraph`（状态图） | 装节点和边的流程容器 | `agent/graph.py:27` | `StateGraph(AgentState)` —— 状态契约是 `AgentState` |
| `node`（节点） | 一个步骤：收 state、返回要更新的字段 | `agent/graph.py:30-33` | 4 个：`iter` / `tools` / `synth` / `reflect` |
| `edge`（边） | 无条件连线，下一跳固定 | `agent/graph.py:51,54` | 2 条：`tools→iter`（ReAct 循环）、`synth→reflect` |
| `conditional edge`（条件边） | 由一个函数决定下一跳去哪 | `agent/graph.py:40,57` | 2 条：`should_continue`、`after_reflect` |
| `State` / state schema（状态契约） | 全图节点共享的数据结构 | `agent/state.py:59` | `AgentState`（TypedDict, total=False），9 字段 |
| `reducer`（归约器） | 规定"节点返回的新值怎么跟旧值合并" | `agent/state.py:23,43,48` | 3 个：`_reset_or_inc` / `_inc_refl` / `_merge_tool_status` |
| `Annotated`（把归约器绑到字段上） | Python 语法，给字段声明合并规则 | `agent/state.py:90` | 每个字段用 `Annotated[T, reducer]` 声明 |
| `add_messages`（消息归约器） | LangGraph 内置，把新消息追加进消息历史 | `agent/state.py:19` | `messages` 字段用它 |
| `compile()`（编译） | 把图定义变成可执行对象 | `agent/graph.py:70` | `build_graph()` 返回它，`runtime._get_graph()` 缓存它 |
| `invoke()`（调用） | 跑完一次完整图 | `agent/runtime.py:101` | `graph.invoke({messages, deadline}, config)` |
| `recursion_limit`（递归步数上限） | LangGraph 兜底上限，超了抛 `GraphRecursionError` | `agent/runtime.py:91` | `RECURSION_LIMIT = 8×4+10 = 42`（按 `MAX_ITER`/`MAX_REFL` 推导，不写死） |
| `bind_tools`（绑定工具） | 把工具说明交给 LLM，让它能发起函数调用 | `agent/nodes/iter_node.py:40` | 只有 iter 节点挂；synth/reflect 不挂 |
| `tool_calls`（工具调用请求） | LLM 说"我要调 X、参数是 Y"的结构 | `agent/nodes/iter_node.py:100-108` | `should_continue` 靠它决定走 `tools` 还是 `synth` |
| `ToolMessage`（工具回执） | 工具执行结果回给 LLM，必须与 tool_call 的 id 配对 | `agent/nodes/status_tool_wrapper.py:123` | 失败时内容是结构化 JSON 载荷，成功时是原始 chunks |
| `ToolNode`（工具节点） | LangGraph 现成的工具执行节点 | `agent/graph.py:25` | `ToolNode(ALL_TOOLS, wrap_tool_call=status_wrapper)` |
| `wrap_tool_call`（工具调用钩子） | 官方拦截点，能包住每一次工具调用 | `agent/graph.py:25` | 官方文档关键词：`ToolNode(wrap_tool_call=...)` |
| `Command`（命令） | 节点返回"要写回 state 的内容" | `agent/nodes/status_tool_wrapper.py:104` | `Command(update={"messages":[...], "tool_status":{...}})` |
| `with_structured_output`（结构化输出） | 让 LLM 输出被 Pydantic 校验的固定结构 | `agent/nodes/reflect_node.py:51` | `with_structured_output(ReflectOutput)` |
| `checkpointer`（检查点）/ `thread_id` | 持久化会话状态用的 | `agent/runtime.py:92-93` | **本项目没装 checkpointer** → `thread_id` 没人读 → 无多轮记忆 |
| `Runnable`（可运行单元） | LangChain 里可调用对象的统一接口 | `agent/llm_wrapper.py:67` | `ThinkingStripRunnable` 包装它，转发 `bind_tools` / `with_structured_output` |
| `total=False`（字段全可选） | TypedDict 语法，state 字段可以不都出现 | `agent/state.py:59` | `AgentState(TypedDict, total=False)` |

## 栏 2 · Milvus

| 术语 | 一句话作用 | 位置 | 本项目怎么用 |
|---|---|---|---|
| `collection`（集合） | 向量数据表 | `utils/txt_spliter/vector_main.py:110` | 真实名 `txt_data_<时间戳>`，每次重建都新建一个 |
| `alias`（别名） | 一个稳定名字，指向某个真实 collection；查询只认 alias | `utils/txt_spliter/vector_main.py:92,156,161` | alias 名固定为配置里的 `collection_name`（默认 `txt_data`） |
| `schema` / `field`（字段定义） | 集合的列结构 | `utils/txt_spliter/vector_main.py:104-107` | 3 个用户字段：`id`(INT64,主键,自增) / `vector`(FLOAT_VECTOR,1024 维) / `text`(VARCHAR) —— 另有隐式 `$meta`(JSON) 动态字段，因为 `enable_dynamic_field=True` |
| `load_collection`（加载） | 查之前必须先把集合载入内存 | `utils/txt_spliter/vector_main.py:144`、`core/rags/rags.py:106` | 索引侧建完就 load；查询侧发现不是 `Loaded` 就补 load |
| `segment`（数据段）/ insert 异步落盘 | 集合底层分块；insert 完**不一定立刻查得到** | `utils/txt_spliter/vector_main.py:131` | 切 alias 前没 flush → 切完一小段时间查不到（§8 P3-10） |
| `flush`（落盘） | 强制把未落盘数据刷下去 | `utils/txt_spliter/vector_main.py`（**没做**） | 已知缺口 P3-10 |
| `partition`（分区） | 集合内的子集 | — | **本项目未使用** |
| `consistency`（一致性级别） | 控制读到什么程度的数据 | — | **本项目未显式设置** |
| `MilvusClient`（pymilvus 客户端） | 只认 `uri` 参数，不认 host/port | `core/rags/rags.py:86` | `MilvusClient(uri=f"http://{host}:{port}")` —— host/port 会被静默忽略 |
| `Web UI` / `Attu` / `milvus_cli` | 三条可视化入口 | `docker-compose.yml:3,10` | **本项目 Milvus v2.3.14 没有 Web UI**（`/webui` 实测 404）；用 **Attu**（`--network ragmi_ragmi-net`，地址填 `milvus:19530`）或 pymilvus 直接查 → 见速览 §2.10 |

> `index`（索引）本项目用 `AUTOINDEX` + `COSINE`（`utils/txt_spliter/vector_main.py:139-140`），不展开。

## 栏 3 · 本项目自有说法

| 术语 | 一句话作用 | 位置 | 本项目怎么用 |
|---|---|---|---|
| `READY` / `SIGNAL_READY` | iter 节点"不调工具了"的流程标记 | `agent/constants.py:50` | 也用于 LLM 调用失败的兜底 |
| `SIGNAL_MAX_ITER` / `SIGNAL_EXPIRED` | 两种"收摊"标记（迭代超限 / 总时限到） | `agent/constants.py:51-52` | iter 节点在边界/超时时写入 |
| `INTERNAL_SIGNALS` | 上面三个的集合，用来把占位消息从答案里剔掉 | `agent/constants.py:54` | `runtime._extract_answer` 用它过滤 |
| `iter_count` / `reflection_count` | 两个计数器：前者可重置，后者永不重置 | `agent/state.py:66-69` | 前者归 `iter` 管，后者归 `reflect` 管 |
| `MAX_ITER` / `MAX_REFL` | 两个上限，来自 YAML | `agent/constants.py:16-17` | `iter.max_per_cycle=3` / `reflect.max_absolute=3` |
| `tool_status` 四态 | success / empty / timeout / error | `agent/nodes/status_tool_wrapper.py:59-64` | 由 `wrap_tool_call` 钩子写入 `state["tool_status"]` |
| `code` / `retryable` | 机器可读失败码 / "这次失败重试有没有意义" | `agent/nodes/status_tool_wrapper.py:59-64` | `OK` / `EMPTY_RESULT` / `TOOL_TIMEOUT` / `TOOL_ERROR`；只有 timeout 为 `true` |
| `app 级单例`（app-level singleton） | RagModel 挂在 app.state 上，全进程只建一次 | `api/dependencies.py:38-53` | FastAPI 的 `Depends` 缓存只跨一次请求，所以贵依赖必须自己做单例 |
| `原子切换 alias` | 新集合建好后让 alias 指向它，旧集合不删 | `utils/txt_spliter/vector_main.py:146,156,161` | `alter_alias()` / `create_alias()` |
| `RetrievalError` | 检索**失败**（严格区别于"检索为空"） | `core/rags/rags.py:11` | 由 `rag_tool.py` 翻译成 `AgentTimeoutError` / `AgentToolError` |
| `AgentError` / `AgentTimeoutError` / `AgentToolError` | 工具层归一化后的两个语义：可重试 / 不可重试 | `agent/errors.py:33-42` | 归一化只发生一次，在工具里 |
| `Timer`（单次动作超时） | 给任意同步调用套时间上限 | `agent/timeout.py:22` | 只能"不再等"，杀不掉线程 |
| `deadline`（图级总时限） | 整张图的总预算，写进 state | `agent/runtime.py:106` | 绝对时间戳，各节点协作式检查 |
| `is_expired()` | 节点进图前问一句"超没超总时限" | `agent/timeout.py:57` | 3 个节点直接调用（iter/synth/reflect）；2 个条件边改查标志位 `state["expired"]` |
| `ThinkingStripRunnable` / `strip_thinking` | 剥掉推理模型吐出的 `<think>` 块 | `agent/llm_wrapper.py:29,67` | 包装在**最内层**，所有派生都受益 |
| `collect_round_material`（本轮素材） | 取"最后一条 HumanMessage 之后的全部 ToolMessage" | `agent/nodes/material.py:15` | iter / synth / reflect 三节点共用同一口径 |
| `next_action`（end / rewrite / re_iterate） | reflect 的三种决策 | `agent/nodes/reflect_node.py:33` | 决定 `after_reflect` 走哪条边 |
| `last_critique` | reflect 写的修改方向，synth 重写时读 | `agent/state.py:75` | 是**覆盖**不是历史（P2-3） |
| `悬空 tool_calls` | 有 tool_calls 但没有 ToolMessage 的 AIMessage | `agent/nodes/iter_node.py:70-73` | MiniMax 会因此报 400 |
| `ReAct 循环` | 决策 → 调工具 → 看结果 → 再决策 | `api/api_agent.py:31` | 图上就是 `iter → tools → iter` 这条无条件边 |
| `retrieve()` | RagModel 的公开检索入口，只返 chunks 不调 LLM | `core/rags/rags.py:149` | Agent 工具只调这一个公开方法 |
| `resolve_embed_settings()` | 索引端与检索端共用的嵌入模型名/base_url 唯一来源 | `utils/txt_spliter/vector_main.py:20` | 必须在 `EmbeddingModel` 构造**之后**调用（它内部才 load_dotenv） |
